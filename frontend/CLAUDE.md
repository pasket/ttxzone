# Frontend (`frontend/`)

Loaded when working under `frontend/`. Cross-cutting rules are in the root `CLAUDE.md`; feature detail in `docs/` (index there). Active org/exercise state (`AuthContext`, `reconcileId`, `resolveDefaultContext`): `docs/architecture/rbac-and-multi-org.md`.

## Wiring

- **Tailwind v4, CSS-first** via `@tailwindcss/vite` — no `tailwind.config.js`. Dark mode is a manual `.dark` class variant (`@custom-variant dark` in `src/index.css`). `index.html`'s static `class="dark"` is only the pre-hydration default; `ThemeProvider` reconciles it with the stored preference.
- **i18n**: `src/lib/i18n.ts` initializes i18next synchronously with inline resources from `src/locales/{en,es}.json`. Extend those files; never introduce async/backend loading or per-feature namespace files. Typed keys reject dynamic template-literal `t()` calls — use a lookup record (e.g. `lib/roleLabels.ts`'s `ROLE_LABEL_KEYS`).
- **ESLint** flat config (`eslint.config.js`): `typescript-eslint` + `react-hooks` + `react-refresh`, hook rules wired manually as `plugins: {...}` + `rules: {...spread}` (their flat exports don't compose via `extends`) — follow that for new plugin rule sets.
  - `react-hooks/set-state-in-effect`: an effect must not call an external function that itself calls `setState` (e.g. a memoized `refresh`). Inline the async fetch + a `cancelled` guard in the effect (see `AuthProvider`).
  - `react-refresh` (components-only exports): a context and its hook can't share a file with the `Provider` component. Use the three-way split — plain store module exporting `createContext` (`lib/authStore.ts`), `.tsx` exporting only the Provider (`lib/AuthContext.tsx`), hook in `src/hooks/` (`useAuth.ts`). Same for theme (`themeStore`/`ThemeContext`/`useTheme`) and toasts (`toastStore`/`ToastContext`/`useToast`).
  - `react-hooks/purity` rejects impure calls (`Date.now()`) during render — derive "age" from payload timestamps (e.g. a dashboard's `generated_at`).
- **StrictMode footgun**: an effect that POSTs something non-idempotent on mount (e.g. `TotpEnrollment`'s `/auth/totp/enroll`, a new secret per call) needs a `useRef` guard so the request fires once, and must **not** also use a cleanup-set `cancelled` flag — StrictMode's mount→cleanup→remount flips it before the one real request resolves and the result never reaches state (`enrollStarted` ref, no `cancelled` on purpose). Idempotent GET effects keep the normal `cancelled` pattern.
- **Dependencies**: no form library (`react-hook-form`/`zod`) — plain controlled inputs. No new deps casually; `qrcode` (TOTP QR as a data-URL `<img>`) is the narrow exception. No chart, icon or state library.

## Routing (`App.tsx`)

- **Code splitting**: each module is a chunk of its own, so a Player doesn't download the Creator and moving between a module's sections downloads nothing. A new section is exported from its module's barrel (`components/<area>/<area>Routes.ts`; `playground/` has `playerRoutes` and `controlRoutes`, so a Player doesn't get the Controllers' panels) and declared in `App.tsx` with `lazyNamed` (`lib/lazyNamed.ts`), never imported statically there. Sign-in screens and layouts stay in the entry chunk. `common/RouteBoundary` wraps what a route renders from a chunk (`<Routes>` and each layout's `<Outlet/>`): loading state, and a reload offer if the chunk never arrives. `lib/staleChunks.ts` reloads once when a tab open across a deployment asks for a chunk that's gone. The locales stay in the entry chunk (see i18n above). The browser tests run the Vite dev server, which has no chunks: `npm run e2e:build` checks the built image (`docs/features/e2e-tests.md`), and CI runs it.
- One `<BrowserRouter>`. A temporary password (`status` `needs-password-change`) goes to `/account/password` before any other gate, then an unconfirmed email address (`needs-email-verification`, also past the periodic reconfirmation's grace period, whose banner `common/EmailReconfirmBanner` sits under both layouts' `Header`) to `/account/verify-email`. The email links open `/reset-password`, `/verify-email` and `/join` (an email invitation) (public routes, token in the fragment), and the sign-in page links to `/forgot-password`. Guards: `RequireAuthenticated` (`/account/settings/*`, reachable while held at the mandatory-TOTP gate), `RequireFullAccess` (everything else past that gate). `/account/organizations/new` (Create organization, from the avatar menu and the Waiting Room) is `RequireFullAccess` without `RequireModule`, so an account with no role reaches it.
- `/platform/{tenancy,accounts,security,organizations,legal,email,sso,activity}` (menu order; administrators are Accounts filtered by `?admin=yes`) and `/platform/accounts/:userId` (one account's page) (instance administrator only, `RequireInstanceAdmin`): `PlatformLayout` reuses the menus as `SectionNav`/`MobileSectionNav` (the presentational halves of `PrimaryNav`/`MobileBottomNav`) with `PLATFORM_SECTIONS` (one section per file in `components/platform/`); not a `ModuleName` — the org-scoped helpers in `moduleAccess.ts` never see it, and the ContextBar renders `PlatformScope` there.
- `/admin/:section?`, `/creator/:ttxId?/:section?`, `/control/:ttxId?/:section?`, `/playground/:ttxId?/:section?` are children of one layout route (`<RequireFullAccess><AuthenticatedLayout/></RequireFullAccess>`). Admin is org-level (no `:ttxId`).
- **Literal sibling routes without `:ttxId`** are declared _before_ each catch-all (static beats dynamic): `/creator/exercise`, `/creator/exercises/new`, `/creator/needs`, `/creator/msel`, `/creator/conduct-prep`, `/creator/players` (`/pending`, `/invitations`), `/playground/enrollments`, `/creator/exercises` and the library routes (`LIBRARY_SUB_KINDS`). They skip `RequireSection`/`RequireTtxParam`.
- `RequireTtxParam` (`components/layout/`): a bare `/creator`/`/control`/`/playground` redirects to the first qualifying exercise; when the URL names an exercise it becomes the context (`followTtx`: that exercise _and its organization_, so a link into another org's exercise switches the ContextBar too).
- `RequireSection`: a missing/invalid `:section` redirects to the module's first **TTX-scoped** section (`ttxScopedSections(sectionsForModule(module))`) — never an `orgScoped` one, which would drop the `ttxId`.
- The live session is `components/playground/` + `hooks/useRunFeed` (polls `GET /ttx/{id}/run?since=` every 3 s as a background request, 204 = no change; `apply` takes a Controller action's answer) + `lib/run.ts` (scenario clock, T+).

## Authenticated shell (`src/components/layout/`)

- `AuthenticatedLayout` = `Header` (logo/avatar row + `ContextBar`) + `PrimaryNav` + `<Outlet/>` + `MobileBottomNav`. No nav-state context: active route from `useLocation()`/`useParams()`; the only local UI state is the mobile drawer, avatar dropdown and the Primary Menu's fold (`hooks/useNavCollapsed`, `localStorage` `ttx_nav_collapsed`): folded, `PrimaryNav` becomes a 64px icon rail (`SectionIcon`, keyed by `SectionDef.key` — a new section needs a glyph there) and the content cap grows by the width the menu gave back (`max-w-[1584px]` → `max-w-[1736px]`), so menu + content keep the same right edge folded or not. Content width: one cap for every module screen, left-aligned — below it the page fills the space beside the menu, above it eye travel stays bounded. `<main>` is `min-w-0` so a wide row (phase strip, storyline) scrolls inside its panel, never the page. Nav components read `useAuth()` directly; the only fetch is the Creator menu's count of what each document needs fixed (`hooks/useDocumentAttention`, `GET /ttx/{id}/attention` as a background request). The header's `AssistantPendingMenu`, before the glossary, shows the AI proposals waiting on the exercise in context and where (`hooks/useAssistantPending`), only while some do. Both stay live without reloading: `apiFetch` sends `DATA_CHANGED_EVENT` after any write of the page that went through (never a GET, a background call or a failure), both read again on it and on window focus, and every `LIVE_REFRESH_MS` (15 s; the menu twice that) while the tab is visible, as background requests, for what changes outside the page (the AI client proposing, a teammate's save); new proposals send `PROPOSALS_ARRIVED_EVENT`, which an open proposals panel reads in.
- `lib/moduleAccess.ts` — pure visibility logic scoped to the **active organization** (`actsAs`, `moduleForRole`, `getVisibleModules`, `ttxOptionsForModule`, `ttxOptionsForRole`, `heldRoles`, `currentContextRole`, `contextEntry`, `resolveDefaultContext`/`routeForContext`, `contextForOrgSwitch`, `MODULE_DEFS`, `currentModuleFromPath`, `isModuleRoute`). **One module per role**: Admin = Program Manager of that org; Creator = Planner (org membership — so a Planner with no exercise yet can create one — or a `planner` row that `plans`); Control = a row that `controls`; Playground (the Player landing) = Facilitator (`facilitates`), Evaluator, Observer, Player. `actsAs(ttx, role)` mirrors the backend's `TTXAccess.context_roles()`. The Playground's sections are filtered by the acting role (`SectionDef.roles`, `sectionsForRole`, `hooks/useActingRole`) in both the menu and `RequireSection`.
- `lib/navSections.ts` — `SectionDef.group` (`exercise` | `organization`) splits a module's menu into blocks separated by a hairline, **no headings and no folding** (Creator: the ContextBar exercise's sections, then Library; never a tint). The Creator's exercise portfolio is not a menu section: it's reached from the ContextBar's exercise selector (see below). Primary Menu = the active module's sections (`CREATOR_SECTIONS`/`CONTROL_SECTIONS`/`EXECUTION_SECTIONS`/`ADMIN_SECTIONS`, `sectionsForModule`). `orgScoped: true` marks a section whose route has no `:ttxId`; its link is `/${module}/${path}` and it's active when the URL's second segment matches (covers `/creator/players/pending`), else the active section comes from `:section`.
- No module-switch links: switching module/role happens only in the `ContextBar`. From Preferences the logo links to `/`, where `Home()` resolves the landing route: mid-session, the module page last worked on (`lib/lastWorkspace.ts`, recorded by `AuthenticatedLayout`, per tab and per user, cleared on logout); otherwise the saved default context.

## `ContextBar` (`components/layout/ContextBar.tsx`)

The single source of context for every screen and form — **forms never carry their own org/exercise pickers**. Second row of `Header`, `<nav aria-label="Context">`, rendered only on module routes (`isModuleRoute()`; `currentModuleFromPath`'s `'admin'` fallback would otherwise leak it onto Preferences). All controls `h-8`. No visible captions: `sr-only` text on static values, `aria-label` on controls. Classes in `buttonStyles.ts`.

- **One trail, dependency order** — Organization `›` Role `/` Exercise (Admin: Organization `›` Role). The role sits between the two because it is held in the organization and filters the exercises; it keeps its chip look so it reads as a mode, not a crumb.
- **Scope segments** — Organization and Exercise: plain text (`breadcrumbStatic`) with one option, a `<select>` whose border shows on hover/focus (`breadcrumbSelectWrapper`) with several; the "/" (`breadcrumbSeparator`) is rendered by the exercise segment so it never dangles.
  - Org: names via `displayOrgName()` ("Name (Alias)"); switching keeps the acting role when the new org has it (else its first role) via `contextForOrgSwitch`, and calls `setActiveOrganizationId` (the only caller) + navigates to that role's route in one `startTransition` (see `docs/architecture/rbac-and-multi-org.md`).
  - Exercise: backed by `activeTtxId`/`setActiveTtxId`, not `useParams()`. On a ttx-scoped route it updates context and navigates keeping the section; on an org-scoped route it only updates context. Hidden on Admin. In the Playground it lists only the acting role's exercises. In Creator it is always a `<select>` (even with one exercise) ending in an optgroup with **All exercises** (`__all__` → `/creator/exercises`, shown as the value on that page, where a new one is created); it navigates without changing `activeTtxId`. With no exercise, an Exercise Planner gets "+ Create exercise" → `/creator/exercises/new` (hidden on `/creator/exercise` and that page).
- **Role** — read-only pill (`badgeNeutral`) with one held role, a `<select>` (`chipSelectWrapper`) with several; picking one navigates to that role's workspace (`contextEntry`), staying on the exercise in context when the new role acts on it (else that role's first exercise). Labels: `lib/roleLabels.ts` (`CONTEXT_ROLE_LABEL_KEYS`, `ROLE_LABEL_KEYS`). Short labels ("Program Manager", "Planner", like the one-word roles); descriptive copy keeps the long names. Order: Program Manager > Planner > Controller > Facilitator > Evaluator > Observer > Player (labels under `roles.*`, `RoleIcon` per role). No view switch: each role has one workspace, so the Role selector is the only mode control.
- Non-link navigation (every ContextBar control, logout) first asks `useConfirmDiscardChanges()`.

## HTTP and client session state

- `lib/api.ts`'s `apiFetch` is the only fetch wrapper: `credentials: 'include'`, `X-CSRF-Token` from the `ttx_csrf_token` cookie on non-GET, `Accept-Language` = the app's language (`<html lang>`, so API errors come back in it — show `ApiError.message` as is), throws `ApiError` parsed from the unified error envelope.
- A 401 meaning "no valid session" (`NOT_AUTHENTICATED`/`TOKEN_EXPIRED`/`TOKEN_INVALID` — never `INVALID_CREDENTIALS`) fires `SESSION_EXPIRED_EVENT`. The backend answers 401 `NOT_AUTHENTICATED` (not 403 CSRF) when there's no session cookie, and for token redemption with neither session nor account details, so an expired session is always actionable. `AuthProvider` re-checks `/auth/me` once and, if gone, goes `anonymous` **without** `applySnapshot` (active org/exercise survive). `LoginCard` says "Your session has expired" and returns the **same account** to the page (path + query) it left; another account or a non-in-app path lands on `/` (`markSessionExpired`/`readSessionExpired`/`returnPathAfterLogin`/`clearSessionExpired`, `sessionStorage`).
- A 403 `REAUTHENTICATION_REQUIRED` is caught by `apiFetch`, which asks `lib/reauthentication.ts`'s handler (`common/ReauthenticationHost`, one shared dialog) and resends once confirmed. Idle/hard-timeout warnings: `lib/sessionActivity.ts` + `common/SessionTimeoutWatcher`. See `docs/architecture/session-policy.md`.
- **Downloads**: `apiDownload(path)` fetches with the session (same errors via the shared `failure()`; a step-up refusal asks to re-authenticate and fetches again, like `apiFetch`), saves under the server's `Content-Disposition` name; `hooks/useApiDownload` makes it a link's `onClick` (the `<a href download>` stays for "Save link as…"). `useUnsavedChangesWarning` ignores `download` links.
- **Session state** = `authStore.ts` + `AuthContext.tsx` + `useAuth.ts` (plain Context). `useAuth()` → `{status, user, ttxList, organizations, activeOrganizationId, activeOrganization, setActiveOrganizationId, activeTtxId, activeTtx, setActiveTtxId, refresh, logout, expireSession}`; `status` ∈ `'loading' | 'anonymous' | 'needs-mfa-enrollment' | 'ready'`. The exposed `ttxList` is **already filtered to the active org**.
- `loadAuthSnapshot`: `/auth/me`, then every page of `/ttx` (`limit=200`, roles, modules and the ContextBar's selector need the whole list) + `/organizations/mine` in `Promise.all`. `needs-mfa-enrollment` = `me.mfa_mandated && !(totp_enabled || session.mfa_source === 'provider')` (single sign-on with the provider's MFA, `docs/architecture/sso.md`) — the server works out the mandate from the roles held anywhere and Platform → Sign-in security's per-role rules, deliberately global across orgs.
- Dev proxy: `vite.config.ts` proxies `/api` to `VITE_API_PROXY_TARGET ?? 'http://localhost:8000'` (resolved in the Vite process: host default `localhost:8000`, Compose sets `http://backend:8000`).
- `logout` = `POST /auth/logout` then `refresh()`, which reseeds from the saved default context.

## Tests

Plain `@testing-library/react` `render`/`screen`/`fireEvent` — no `user-event`, no mocking library. `tests/mockFetch.ts`'s `mockFetchOnce` stubs `fetch` per test (reset in `tests/setup.ts`), since `AuthProvider` fetches on every mount. **Import `render` from `./testUtils`**, which wraps `ToastProvider` + `MemoryRouter` (skipped when `ui` is itself a `MemoryRouter`) — otherwise `useToast must be used within a ToastProvider`. Tests start with an empty `localStorage`. Browser tests are apart, in `e2e/` (Playwright, `*.e2e.ts`): `docs/features/e2e-tests.md`.

## Design system

- Tokens from the TTX-Zone Style Guide: dark-first "command center" — near-black `ink`/`surface`/`line` neutrals, IBM Plex Sans/Mono (Google Fonts `<link>` in `index.html`), flat hairline panels, **no shadows on static panels**. A Tailwind v4 `@theme` block in `src/index.css` (real utilities: `bg-ink`, `text-fg-muted`, `font-mono`…) plus `.dark` overrides only where raw values differ (`--color-hover`, `--color-surface-raised`: dark elevation is a lighter tonal surface, light keeps a subtle `shadow-lg`).
- **Text colours have their own tokens**: `text-accent-fg`, `text-success-fg`, `text-danger-fg` and each tag's `text-tag-*-fg` (also `ring-`/`outline-`/`accent-accent-fg`), per theme, 4.5:1 on their surfaces. `--color-accent`, `--color-success` and `--color-danger` are fills and borders; on a light surface they don't reach it. Muted text starts at `text-paper-ink/60`, `/70` on a `bg-paper-line` row.
- **`sr-only` in a scroller**: it's absolute, so a scroller must be its containing block or the page scrolls sideways. `.overflow-x-auto` is `relative` in `index.css`'s base layer; a scroller built another way needs `relative` itself.
- **Landmarks**: the layouts own `<main>` (`AuthLayout` too); a section renders a `<div>`. Each page has one `h1`. `e2e/a11y.e2e.ts` checks all this.
- Reserved colours: `severity-*` only for inject severity, never decorative. `--color-danger` (`#d1373d`) ≠ `--color-severity-critical` (AA with white text; a routine delete mustn't look like a critical alert). `--color-success` (`#1f9d63`). `--color-accent` (brand: nav active state, links, focus) vs `--color-cta` (primary buttons only, more vivid) — the UI stays mostly monochrome, nav stays accent. `--color-tlp-*` only for TLP labels, `--color-inactive-1..3` only for last-login staleness, `--color-tag-*` only for tags, `--color-playhead` only for the control center storyline's live "now" line, `--color-chart-*` only for chart series (validated palette — re-run the dataviz `validate_palette.js` before changing it).
- `--color-ink` `#0c0d10` is mirrored by hand in `index.html`'s `theme-color` and `public/site.webmanifest`.
- `lib/buttonStyles.ts` exports className constants (`btnPrimary`, `btnSecondary`, `btnDanger`, `btnNeutralIconGhost`, `inputBase`, `linkAccent`, `optionalSuffix`, `badgeNeutral`, `segmentedControl`, `actionsHeaderClass`/`actionsCellClass`…) — not a `<Button>` component.
- Radius 4px (`rounded-sm`) for panels and controls; nested segments `rounded-xs`.
- Audience: must read as credible to executives (Legal, PR, HR) as well as technical teams — a Splunk-like dashboard aesthetic; Linear/Vercel-like: clean, high-contrast, generous whitespace, 1px borders, micro-interactions.

## Panels and page layout

- **The page bg is the page; a panel is one object on it** (list, form, settings group, chart). `common/Panel.tsx` (`title`/`meta`, `aside`, `description`, `flush`, `footer`) on `lib/panelStyles.ts`'s `panelClass` (re-exported for dashboards). Surfaces are tokens, not `dark:` pairs: `--color-panel`, `--color-panel-line`, `--color-field` (inputs read inset), floating UI (menus, popovers, help notes) via `buttonStyles.floatingSurface` — `bg-surface-raised` alone is the dark surface on both themes, unreadable in light.
- **One right edge per page**: every module-page panel spans the content width (`max-w-[1584px]`, `max-w-[1736px]` with the menu folded); never cap a panel's width — cap long running _text_ (`max-w-prose`), not its panel. Only a form's _fields_ stay narrow (`panelFormFields` `max-w-2xl`, or `max-w-sm` for short forms) — except the needs analysis and MSEL form tabs, which use the width with framed groups (`common/FieldGroup.tsx`; copy under `creator.needs.fieldGroups.*`/`creator.msel.fieldGroups.*`). Preferences uses its own `max-w-xl` column. Page titles (`SectionHeader`) and their "+" stay on the bg. Descriptions are not width-capped.
- **Long descriptions fold** via `common/HelpText` (`id` = i18n key): one line → whole; longer → first line truncated + "Show more" (`linkAccent`, 13px, chevron), "Show less" when open, `aria-expanded`/`aria-controls`. Fit measured with a `ResizeObserver` (`scrollWidth > clientWidth` folded, `getClientRects` open, counting rects that start lower, since an `<abbr>` splits one line into several; none in jsdom = whole). Open on first encounter, folded afterwards (`lib/helpText.ts`, `localStorage` `ttx_help`, try/catch). Chart descriptions and `FieldGroup` hints stay plain. A description that explains several roles uses `common/RoleGuide` (intro sentence + a role → what-it-does list behind the same Show more / Show less memory). People × roles tables share `common/RoleMatrix` (`RoleColumnHeader`, read-only `RoleMark`); changes happen in each person's editor, never by ticking cells.
- **Sub-pages are tabs under the page title** (`common/PageTabs`: links, so each keeps its URL) — Library's kinds, Invitations' Overview / Pending requests. There is no second menu column.
- **Three patterns only**:
  - **List** = one flush panel; count (`<ns>.count_one/_other`) + `TableToolbar` in the header; cells via `panelTableHeadRow`/`panelTh`/`panelTbody`/`panelTr`/`panelTd`/`panelActionsTh` (`lazyRow` adds `content-visibility: auto` for long unpaginated lists — MITRE groups, the ATT&CK picker, the inject catalog); centered empty state; `Pagination` in the footer only with >1 page. Page/sort/search in the URL (`hooks/useTableUrlState.ts`, `?page=&sort=&dir=&q=`, defaults omitted, per-table prefix) + `usePageFallback` (back to page 1 when the page vanishes).
  - **Create/edit form** = panel with explanation in `description`, Cancel then the committing action right-aligned in the footer (`panelFormActions`); replaces the list while open.
  - **Settings** = stacked panels, one per independent decision.

## Forms

- **Unsaved changes**: `useUnsavedChangesWarning(dirty)` (`lib/unsavedChanges.ts`) adds `beforeunload` and confirms same-origin link clicks in the capture phase (`common.unsavedChangesConfirm`); non-link navigation uses `useConfirmDiscardChanges()`.
- **Edit modes live in the URL** (`hooks/useEditModeParam.ts`, `?edit=1`) so reload/links open them and Back leaves them.
- **Optional fields** get a muted suffix: `{t('…Label')} <span className={optionalSuffix}>({t('common.optionalSuffix')})</span>`. Conditionally required fields stay plain.
- **Placeholders never restate the label**: empty by default; a short format/example hint (`…Placeholder` key) only where it clarifies shape (emails `you@company.com…`, 6-digit codes `123456…`, bare domains `acme.com…`, description examples). Every placeholder ends with "…". A typed-confirmation field's placeholder is the value to type.
- Tag assignment stays in each entity's form (`TagAssignmentField`, staged until Save) with a "Manage tags in the Library" link.

## Tables

- **Actions column always last, always visible**, header right-aligned — never hidden behind a per-row edit mode. `actionsHeaderClass` (`w-24`, fits two `h-9` icon buttons) + `actionsCellClass`, even with one button. Exception: Pending requests' Approve/Reject (text button) gets only `text-right`/`justify-end`, auto width.
- **Library tables read as text**: the main column (`panelMainTh`) takes the spare width and shows `LibraryItemText` (name + two clamped lines); counts are their own right-aligned columns (`panelNumTh`/`panelNumTd`), not words in a sentence; languages are codes (`AvailableLanguages`); `libraryActionsCellClass` keeps the icons visible but frames them only on hover or focus.
- Edit = explicit `common/EditButton` (pencil, `btnNeutralIconGhost`), never row-click. Overlays only via `common/Modal` (focus trap, Escape/backdrop close, nested dialogs close alone, returns focus to the opener with `preventScroll` — callers must not refocus an "Add" button themselves; `size="lg"`/`"xl"`, `align="top"`).
- **Removal**: `IconButton` trash + `useUndoableAction` (optimistic remove, Undo toast, no confirm dialog; focus moves to the next/previous row's same control, back on Undo). Removing a Program Manager or a planning-team member, deleting an organization or an account asks for the typed full name instead (more consequences than revoking a token). In autosaved documents (needs analysis, MSEL) rows go through `hooks/useUndoableRowRemoval.ts` (the row leaves the draft at once; autosave is held until the Undo window closes, since a saved row's id can't be put back — `NEEDS_FORM_ROW_NOT_FOUND`; Undo re-inserts it into the current draft). Approvals and evidence files defer their `DELETE` through `useUndoableAction`.
- `<details>` dropdown menus use `hooks/useDisclosureMenu.ts` (Escape, click-outside, close-on-pick).
- **Sort field**: every `TableToolbar` uses `SortFieldMenu` (icon button "Sort by: Name" → `menuitemradio` menu; Arrow/Home/End, Enter/Space, Escape/Tab return focus). `sortOptions` default `created_at`/`name`; `sortLabels` renames misleading ones (Allowed Domains "Domain", Invitations "Description", "Date requested" for request lists).
- **Last login** (`common/LastLogin.tsx`, `lib/lastLogin.ts`): relative time + exact date on hover; past 3/6/12 calendar months a tinted chip on `--color-inactive-1..3` with a distinct icon per level and `sr-only` text; `null` = "Never". People tables sort by it via `lib/peopleTable.ts`'s `PEOPLE_SORT_OPTIONS` (passed to both `useTableUrlState(prefix, sortOptions)` — unknown `?sort=` falls back — and `TableToolbar`). Exercise Planners sorts server-side (`?sort_by=last_login`); unpaginated tables use `filterAndSortPeople`. Never-logged-in rows are least recent. `User.last_login_at` exists for every role — a future Players table only adds it to its read schema.

## Action feedback

- `useToast().showToast(message)` (`components/common/Toast.tsx`): floating card, bottom-center on mobile, top-right on `lg:`, `border-l-success` strip, auto-dismiss 3s, stacks. `ToastProvider` wraps `<Router>` inside `<ThemeProvider>` in `App.tsx`.
- `common/ButtonSpinner` replaces a button's label while its `submitting`/per-row flag is true; `ConfirmButton` has `pending`.
- Wire both at every real save/create/approve/reject/join/leave. Not for TOTP enroll/disable or backup-code regeneration (their confirmation view must stay on screen), login/register/waiting room (own confirmation screens), or instant-apply controls (theme, selects) whose own state is the feedback.
