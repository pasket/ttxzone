# Backend (`backend/`)

Loaded when working under `backend/`. Cross-cutting rules are in the root `CLAUDE.md`; feature detail in `docs/` (index there). Endpoint catalog: `docs/architecture/api-endpoints.md`. Roles and guards in depth: `docs/architecture/rbac-and-multi-org.md`. Sessions: `docs/architecture/session-policy.md`.

## Layout
- `app/core/` is infrastructure, not features. Features live in `app/models/`, `app/schemas/`, `app/services/` (per domain) and `app/api/v1/endpoints/` (each router included in `app/api/v1/api.py`'s `api_router`). Code-level catalogs (regulations, actors, injects, tags, ATT&CK, the knowledge base) live in `app/data/`.
- `core/db.py` — SQLModel `engine` + the `get_session()` dependency.
- `core/config.py` — the single `Settings` (pydantic-settings, `.env`, computed `DATABASE_URL`). All config goes through it; never read `os.environ` elsewhere.
- Dependencies are pinned in `requirements*.txt`. Upgrade deliberately: bump the pin, `docker compose up -d --build backend`, full suite + `alembic check`.
- Migrations: Alembic. The test suite builds its schema with `SQLModel.create_all`, so only CI's `alembic upgrade head` + `alembic check` exercises migrations — a model change without a migration fails CI. Adding a Postgres enum value needs `ALTER TYPE … ADD VALUE` in an autocommit block. Back up the dev DB before a data migration.

## Database conventions
- **Timestamps are timezone-aware UTC** (`core/db.py`): SQLModel maps every `datetime` to `UTCDateTime` (`TIMESTAMP WITH TIME ZONE`), which rejects naive datetimes at bind time. Always `datetime.now(UTC)` — never `.replace(tzinfo=None)`, `utcnow()` or bare `datetime.now()`. Normalize naive request input to UTC in the schema validator (see `InvitationTokenCreateRequest.expires_at`). SQL weekly buckets use `date_trunc('week', created_at AT TIME ZONE 'UTC')`, never the session TimeZone.
- **No FK carries `ON DELETE CASCADE`**: deletes run in dependency order in the service (see `organization_service.delete_organization`, `delete_msels_for_ttx` before `delete_forms_for_ttx`, `delete_tag_assignments`). Add a new child table to the relevant cascade.
- Without ORM relationships the unit of work doesn't order inserts by FK — flush level by level when a save creates a tree (see `ttx_msel_service`).
- Concurrency invariants ("never zero Program Managers / Planners") lock the rows (`SELECT … FOR UPDATE`) before counting.
- Response schemas carry emails as plain `str`, never `EmailStr` (a deleted account's placeholder `…@deleted.ttx-zone.invalid` must still load).
- Uploaded files that may hold exercise content (approval evidence) are never `StaticFiles`-mounted: served only through a guarded endpoint (`attachment`, allowlisted content type, `Cache-Control: private, no-store`), validated by extension *and* leading bytes, unlinked in an `after_commit` hook.

## Security (`core/security.py`, `core/middleware.py`)
- Argon2 hashing; JWT in an HttpOnly cookie + a readable CSRF cookie (`set_auth_cookies`, `verify_csrf` double-submit). The JWT carries only `sub` and `sid`; roles are resolved from the DB per request. Never call `set_auth_cookies` directly — sessions go through `start_session`. `clear_auth_cookies` must mirror the cookie attributes exactly.
- **Guards** (detail in `docs/architecture/rbac-and-multi-org.md`):
  - Program Manager: `require_program_manager_of` (org from the URL — every `/organizations/{organization_id}/…` Admin route), via `require_program_manager` / `is_program_manager`. On exercises a Program Manager only reads (see below) and deletes (`DELETE /ttx/{ttx_id}` guards itself).
  - Planner (org scope): `require_planner(session, user, organization_id)` with the org explicit (e.g. `POST /ttx` body). Never reintroduce an auto-resolving "the Planner's org" helper.
  - Exercise scope: `RequiresOrgAndTTXAccess(*allowed_roles)` (a Program Manager of the owning org passes on `GET`/`HEAD` only — oversight, never design; otherwise, and on every write, a `TTXAccess` row whose `context_roles()` include a listed role — `RoleEnum.PLANNER` means the row `plans`; `TTXContextRole.CONTROLLER`/`FACILITATOR` select the `controls`/`facilitates` flags; no implicit hierarchy; 403 `TTX_ACCESS_DENIED` with `ttx_id`). Its logic is `require_ttx_role(session, user, ttx, allowed_roles)` for callers keyed by something else (e.g. a `token_id`).
  - Organization library: writes `require_library_manager` (Program Managers only); lists `require_library_reader` (Program Managers *and* org Planners, who copy into their exercises).
  - **Mandatory TOTP** per role as Platform → Sign-in security sets it (`security_policy_service`; default Program Manager, Planner — any planning and control team member —, Evaluator and Observer; Player opt-in; the instance administrator always) via `_require_mfa_for` (403 `MFA_REQUIRED`) on every path, including the Program Manager's read access. A new guard passes the roles it acts in, never a hard-coded mandate. `mfa_satisfied` also accepts a session opened through single sign-on whose provider did MFA (`UserSession.mfa_source`, `docs/architecture/sso.md`).
  - The MFA-pending JWT (`create_mfa_pending_token`, ~5 min) is never accepted by `get_current_user` or any guard.
  - **Read the caller's grant through `ttx_access_of(session, user_id, ttx_id)`** (and memberships through `is_program_manager`/`is_disabled_in_organization`): kept for the request in `request_memo(session)`, forgotten on any flush. Code that changes grants reads them itself. Deployment-wide rules (password/MFA policy, required legal versions) are cached per process `INSTANCE_CACHE_SECONDS` -- a save must call `forget_cached_policies()` / `forget_cached_versions()`. `tests/test_request_queries.py` budgets a Player's `GET /run` (7 statements).
- **Step-up**: `RequireRecentAuthentication` (in `dependencies=[...]`) or `require_recent_authentication(current)` → 403 `REAUTHENTICATION_REQUIRED` unless re-authenticated within `STEP_UP_MINUTES`. Required on a new endpoint that touches **the account's own credentials** (password, second factor, tokens, single sign-on link) or **Platform**. Organization and exercise work (approvals, sign-offs, deletes, joining, leaving) gets no step-up: it records a Platform activity event instead (`platform_audit_service.record` / `record_exercise`, a new `AuditAction` + its label in `PlatformActivitySection`), and an irreversible delete keeps a typed name checked by the server. List in `docs/architecture/session-policy.md`.
- **CSP**: `SecurityHeadersMiddleware` adds baseline headers and a deny-all API policy (`API_CONTENT_SECURITY_POLICY`; `/docs` and `/redoc` exempt). The SPA's policy is a build-time `<meta>` from `vite.config.ts`'s `contentSecurityPolicy()`: `'self'` scripts/styles/API, Google Fonts (`fonts.googleapis.com` styles, `fonts.gstatic.com` fonts), `img-src 'self' data: blob:` (TOTP QR, upload previews), `style-src-attr 'unsafe-inline'` (React `style` attributes); no inline `<script>`/`<style>` elements; new origins go there. Build only (the dev server injects inline React Refresh scripts); `vite preview` shares the dev proxy to try the build with its policy. `frame-ancestors` can't be set by `<meta>`, so production must send it as a header.
- **PDFs** (reportlab): all user text goes through `html.escape` before `Paragraph` (reportlab parses markup — an unescaped `<img src=…>` reads local files). Not `xml.sax.saxutils` (Bandit B406). Shared helpers in `services/pdf_common.py` (fonts, TLP label top and bottom, logo, tables, `build_pdf`, `code_ref`). Copy lives in `*_pdf_labels.py` mirroring frontend labels; `?lang=` because a download link sends the browser's Accept-Language.
- **Email** goes out only through `email_service.queue(...)` inside the action's transaction (outbox, sent by a background loop) — never `smtplib` or a send from a request. Outgoing HTTP to a single sign-on provider goes through `oidc_service` (no-redirect opener, https only). A new secret the app stores in its own database goes through `core/crypto.py` (`DATA_ENCRYPTION_KEY`), never as plain text. Detail: `docs/architecture/email.md`.
- **SSDLC for every endpoint**: strict Pydantic validation, safe CORS (`BACKEND_CORS_ORIGINS`), CSRF, server-side sessions, step-up where sensitive, clean under the blocking CI security job (Bandit, `pip-audit`, `npm audit`).

## Errors and logging
- `core/exceptions.py`'s `AppException(code, message, status_code, ttx_id, log_level, logger_name)`; `app/middlewares/exception_mw.py` wraps every request. Clients only ever get `{"success": false, "error": {"code", "message", "ttx_id"}}`. Keep every endpoint compatible with it, one code per error (detail goes in a validation report, not extra codes).
- **Last login**: `auth_service.record_login` (sign-in) and `record_signup` (org signup, bare registration, redemption creating an account) stamp `User.last_login_at` whenever a session is issued, and record `auth.login` / `auth.register` — never on a failed attempt or at the MFA-pending step. Exposed on `PlannerRead`/`ProgramManagerRead`/`PlanningTeamMemberRead`; server-side sort uses `NULLS LAST` desc / `NULLS FIRST` asc.
- `message` goes out in the client's language (`Accept-Language`, which the SPA sets to its own, `core/i18n.get_locale`): written in English at the raise site with `{placeholders}` filled from `AppException(..., params={...})` — never an f-string — and translated by `translate_error` from `app/locales/<lang>.json`'s `errors`, keyed by that English text (no `en.json`: English is the source). A message built from a label (a role) is one whole message per value, in a `(code, message)` table. `tests/test_error_catalog.py` walks the source and fails on an untranslated, stale or f-string message. The same locale picks default exercise risks and seeded actors; PDFs take `?lang=`.
- Levels: `INFO` successful auth / exercise lifecycle; `WARNING` in-scope rejections and client mistakes (pass `log_level=logging.WARNING`); `ERROR` (default) per-request faults; `CRITICAL` infra crashes.
- `core/logging_conf.configure_logging()`: three loggers, each stdout + a file under `backend/logs/` (auto-created, git-ignored), capped by size by default — `RotatingFileHandler`, `LOG_FILE_MAX_MB` (10) × `LOG_FILE_BACKUPS` (5); `LOG_FILE_MAX_MB=0` switches to `WatchedFileHandler` for the server's logrotate (needed with several processes) — `docs/architecture/logging.md`: root → `app.log`; `uvicorn.access` → `access.log`; `app.auth` (`AUTH_LOGGER_NAME`) → `auth.log`, `propagate=False`.
- `auth.log` holds **every authentication event and onboarding**: each `auth.*` event (sign-in and its failures, second factor and lockout, step-up, sign-out, sign-up, password and two-factor changes) written by `auth_event_service.auth_event`, which also records it in Platform's activity log (and so the SIEM) — a new authentication path uses it, never a bare `auth_logger` line; plus onboarding (org creation, token redemption, access-request approve/reject, legal acceptances) and the AppExceptions raised with `logger_name=AUTH_LOGGER_NAME`. Route by passing `logger_name` at the raise site — never by matching on `code` (`INVALID_CREDENTIALS` is shared).

## Tests
- Inside the container always `docker compose exec -T -e POSTGRES_DB=ttx_zone_test backend pytest -q` — `conftest.py`'s `drop_all` would wipe the dev DB otherwise.
- TOTP codes can't be reused across calls (anti-replay): tests must generate a fresh step.
- New Planner-only (design) endpoint → add it to `DESIGN_ENDPOINTS` in `tests/test_ttx_evaluation.py` (asserts an Evaluator gets 403, a Program Manager off the team 403 on writes and no 403 on reads, and in `test_ttx_control_team.py` a Controller who doesn't plan 403).
- Org signup (and `POST /organizations/mine`) grants the founder Program Manager **and** Planner: a test that needs a Program Manager without Planner must revoke it. A test fixture building `TTX(...)` directly must also add the creator's `TTXAccess(PLANNER, plans=True, controls=True)` if the founder then acts on it — a Program Manager without a seat only reads.
- Fixtures building `TTX(...)` directly still get a `code` and a needs form (a `before_flush` hook in `ttx_needs_form_service`). `next_release` (conftest) fakes a future ATT&CK release.
- PDF tests extract text with `pypdf` (dev-only dependency) and search it for forbidden content.
