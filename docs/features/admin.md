# Admin module (Program Manager of the active organization)

Menu: Organization → Users and roles → Exercises → Allowed Domains → Library → Improvement plan. `App.tsx`'s `AdminSectionOutlet` dispatches on `section`, keyed by `activeOrganizationId` so a ContextBar org switch discards open forms. Every route takes the org from the URL (`/organizations/{organization_id}/…`, `require_program_manager_of`).

## Organization (`AdminOrganizationProfileSection`, `/admin/organization`)
- The **profile of the active organization only** (rendered when it `is_program_manager`); the ContextBar picks the org, so there is no org table.
- View: `DashboardPage` "Organization profile" with an **identity band** in its `summary` slot (logo or initials, Name + Alias, Domain, applied org tags, **Edit profile** text button, Delete trash `IconButton`), then the org dashboard. The old `/admin/organization/:organizationId/dashboard` redirects here.
- **Edit profile** (`?edit=1`) keeps the band as read-only context and swaps the dashboard for one profile panel with a single Cancel / Save changes footer. Fields: square logo (`ImageUploadField shape="square"`), Name (required, initial focus; `PATCH` takes an optional stripped `name` — omitted = unchanged, blank = 422) + Alias + Tax ID, Description, Tags (managed in Library → Tags). No Domain input: captured at signup, never editable. Data fetched fresh (`GET /organizations/{organization_id}`).
- The logo is **staged until Save** (object-URL preview, revoked on replace/cancel/unmount). Save: `PATCH` → tag-apply `PUT` → logo `POST`/`DELETE` if pending → `refresh()` (the band reads the auth snapshot). Alias shows in the ContextBar as "Name (Alias)".
- **Delete**: typed-name confirmation → `DELETE /organizations/{organization_id}` `{confirmation}` (the name, checked by the server too; no step-up, recorded as `organization.delete`), an irreversible cascade (`organization_service.delete_organization`): every exercise and everything under it (MSELs, needs forms and evidence files, injects, tokens + redemptions/tag assignments/access requests, `TTXAccess`, exercise tags), org tags, allowed domains, memberships and the logo file, in dependency order (no FK cascades); users whose `default_organization_id` pointed at it get it nulled. Then `refresh()` and navigate to `/`.

## Exercises (`AdminExercisesSection`, `/admin/exercises`)
- The organization's whole exercise portfolio: every exercise of the active organization from the auth snapshot's `ttxList` (`GET /ttx` lists a Program Manager's orgs' exercises, `role: "program_manager"` where they hold no seat), in `common/ExercisePortfolio`'s `ExerciseList` — the same list as Creator → Exercises: code and name, needs analysis and MSEL status, Lead Planner, created; search and sort in the URL.
- **Delete** (`can_delete`, always for a Program Manager): `DeleteExerciseModal`, typed name, no step-up (`DELETE /ttx/{ttx_id}`, recorded as `exercise.delete`).
- **Archive / Unarchive** (`can_delete`): `ArchiveExerciseModal`; the list shows Active exercises by default, Archived / All behind its **Show** filter (`GET /ttx?archived=`); see `docs/features/creator-exercise.md`.
- **Open** only where the Program Manager plans the exercise (`actsAs(ttx, 'planner')`): a Program Manager designs only from a seat on its team. Opening read-only without a seat is still open (`docs/roadmap.md`).
- **Join** (person-plus icon, rows with no seat: `role === 'program_manager'`): `JoinExerciseModal` offers the seats the Program Manager's org grants allow — Exercise Planner, Controller, Facilitator (org Planner grant), Evaluator, Observer (`OrganizationSummary.is_evaluator`/`is_observer`) — and names the others with a link to Users and roles; `POST /ttx/{ttx_id}/people/me` (no step-up, recorded as `exercise.member_joined`), then `refresh()`, and the row opens. More functions come later from the exercise's team.
- Searched (name or code), sorted and paged on the server (`GET /ttx?organization_id=…&q=&sort_by=&sort_dir=&limit=20&offset=`, URL state via `useTableUrlState`), not read from the auth snapshot (which holds them all, for the ContextBar's selector and the roles). Delete and Join refetch the page.

## Users and roles (`AdminUsersAndRolesSection`, `/admin/users-and-roles`)
- A **read-only people × roles matrix**: a row per person holding any grant (name + email), a column per role in hierarchy order — Exercise Program Manager (EPM), Exercise Planning Team (EPT), Observer, Evaluator (`common/RoleMatrix`: header with icon, holder count and the long name; `RoleMark` check / dot) — then Last login, Tags, Actions. Sticky first column, horizontal scroll on narrow screens. The description is a `common/RoleGuide`: an intro sentence, then each role and what it does behind Show more / Show less.
- A role here **authorizes**: an exercise's team then assigns the person on each exercise (`docs/features/creator-exercise.md`).
- Data: `GET /organizations/{organization_id}/members` (`organization_service.list_org_members`): one row per person, `roles`, earliest `granted_at`, union of tags, `disabled`, `role_counts` (active grants); `q`, `sort_by`, `sort_dir`, `role` and `status` (`active` / `disabled`) filters, `limit`/`offset`; URL state via `useTableUrlState` + `?role=` / `?status=`.
- **Edit** (pencil, `Modal`): 1. Roles (checkboxes with what each allows), 2. Tags; one Save → `POST`/`DELETE …/program-managers|planners|observers|evaluators[/{user_id}]` per changed role, `PUT …/members/{user_id}/tags` (one tag set per person, written on every grant). Removing Program Manager asks for the full name (the last one is locked, `LAST_PROGRAM_MANAGER`). No step-up anywhere in Users and roles: the typed name is the confirmation. **Removing any other role cascades** (`_cascade_to_exercises`): the person loses that role on every exercise of the organization — the editor lists those exercises first (`GET …/members/{user_id}/exercises`). A team is never left without a Planner or a Controller (409 `ONLY_PLANNER_OR_CONTROLLER`, naming the exercises); a lead hands over to the longest-standing other Planner.
- **Remove** (trash): typed full name → `DELETE /organizations/{organization_id}/members/{user_id}`. With no exercises, every grant goes (`deleted`). Still on exercises: every grant gets `OrganizationMembership.disabled_at` (`disabled`) — no grant counts (`active_membership()` in every guard and lookup), the org leaves their switcher and its exercises 403 `MEMBER_DISABLED` — until they're taken off those exercises and removed again, or re-enabled (`POST …/members/{user_id}/enable`, restore icon on the row). Opening Remove on someone already disabled and still on exercises says so and lists them, with nothing to submit. The last Program Manager can't be removed. People can also leave on their own (Preferences → Privacy → Leave, `docs/features/preferences.md`), the last Program Manager naming a successor first.
- **Add person** (Create pattern): email + roles + tags, granted in hierarchy order; a failing role (e.g. `DOMAIN_NOT_ALLOWED` — Program Manager and Planner grants are domain-allowlisted, Observer and Evaluator aren't) is listed without losing the others.

## Allowed Domains (`AdminDomainAllowlistSection`, `/admin/settings`)
- `OrganizationAllowedDomain` rows (`GET`/`POST`/`PATCH`/`DELETE /organizations/{organization_id}/allowed-domains[/{domain_id}]`, writes recorded as `organization.allowed_domain`, no step-up). **Default-deny**: only an email domain on the list can become Planner or Program Manager; an empty list allows none.
- Two flags, `allows_program_manager` and `allows_planner` (≥ 1 true). A new domain defaults to Planners only (Program Manager is opt-in); the signup-seeded own domain gets both. Each grant checks its own purpose: `require_email_domain_allowed(…, purpose)` — `"program_manager"` for `grant_program_manager`, `"planner"` for the Planner grant (`grant_member_role`), and the pending-requests `is_allowed_domain` indicator. Approving a Planner-role access request needs the org Planner grant itself (400 `NOT_ORG_PLANNER`), so the allowlist is never bypassed. Player requests are never domain-gated. Shared check: `organization_service.is_email_domain_allowed`.
- UI: two "Applies to" checkboxes on add, an "Applies to" column, one "Edit domain" modal for flags + tags (`PATCH` then tags `PUT`).
- Signup and founding from the avatar menu seed the founder's email domain; under the `open` rule both reject free email domains and non-routable ones first (`docs/features/instance-tenancy.md` → Free email domains), so there it's always a company domain.

## Dashboards
- Layers, kept separate: **generic primitives** in `src/components/dashboard/` (`DashboardPage` with optional `summary`/`actions` slots, `KpiStrip`, `ChartPanel`, `StackedBarList`, `ProportionBar`, `ColumnSeries`, `ChartLegend`, `ChartTooltip`, `DataTable`) take props only — no `apiFetch`, i18n keys or domain types. **Per-module composition** = one aggregate endpoint + one type in `lib/types.ts` + one component mapping it, fetched via `hooks/useApiResource.ts` (`{data, loading, error, refetch}`).
- Backend `app/services/dashboard_service.py` (schemas in `app/schemas/dashboard.py`): grouped SQL counts with a fixed number of queries regardless of exercise count; weekly buckets via `date_trunc('week', created_at AT TIME ZONE 'UTC')` zero-filled to 12 weeks in Python. `GET /organizations/{organization_id}/dashboard` (Program Manager), `get_ttx_dashboard` (`GET /ttx/{ttx_id}/dashboard`, `TTXDashboardRead`: same helpers scoped to one exercise + per-invitation-token request outcomes), `get_planner_overview` (see `docs/features/creator-exercise.md`).
- Shared panels (access requests + invitation stats, weekly joins, load error): `components/common/DashboardActivityPanels.tsx`, `dashboard.*` keys, `lib/dashboardTime.ts` (`parseUtc` — still treats an offset-less value as UTC — `parseDay`, `pendingKpiContext`), `chartTheme.ts`'s `REQUEST_OUTCOME_COLORS`. Module panels stay in `AdminOrganizationDashboard`/`CreatorExerciseDashboard`. Derive "age" from the payload's `generated_at`, never `Date.now()`.
- Charts are hand-rolled HTML/CSS. `ChartPanel` owns loading/empty/error and the optional Chart/Table toggle (`DataTable` = accessible fallback); every mark is focusable with a full `aria-label`; `ChartTooltip` is `aria-hidden`. Colours `--color-chart-1..3` + `--color-chart-other` by series position (`lib/chartTheme.ts`'s `seriesColor()`) — never cycled, never severity/tag colours, text never wears a series colour; validated palette (re-run `validate_palette.js` before changing it). `lib/chartScale.ts`: `niceTicks`/`toPercent`.
