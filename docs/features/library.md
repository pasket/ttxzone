# Library

Menu **Library** / **Biblioteca** (code in `components/templates/`). Five kinds — simulated actors, threat actors, injects, tags and **scenarios** (whole exercises; see `docs/features/scenarios.md`) — each on **three levels**, all **independent of the needs analysis and the MSEL** (managed at any time):
- **TTX-Zone** — a code-level, read-only catalog (both languages, stable slug ids, never real organizations).
- **Organization** — the org's own items, changed only by its Program Managers (`require_library_manager`); org-scoped Exercise Planners list them (`require_library_reader`, each role with its own TOTP mandate) to copy them into their exercises; cascade-deleted with the org.
- **Exercise** — the exercise's own copies.

**Every use is a copy**: no FK points at the library; editing or deleting an item never changes an exercise. Copies record `origin` (`ActorOrigin`) + `origin_id` + `origin_name` (the original's name at copy time, so "Copied from" survives renames/deletes); only a `system` origin id is validated.

**Deleting an organization item that's in use disables it** (`library_usage_service`, tests `test_library_usage.py`):
- **What counts as a use:**
  - exercise copies (`origin=organization` + `origin_id`, indexed on `msel_simulated_actor`/`msel_threat_actor`/`inject`/`ttx_tag`, scoped to the org's exercises);
  - an org inject sent by an org actor (`actor_origin_id`);
  - a tag applied to the organization, a membership or an allowed domain.
  - A library item duplicated from another one does *not* count.
- **Endpoints and the usage count:**
  - `GET …/{id}/usage` returns a `LibraryUsage` (exercises with their copy counts, injects, assignment counts, `total`).
  - Library lists carry `usage_count` (from `usage_counts`, one grouped query per kind) and `disabled_at`.
- **`DELETE` returns a `LibraryDeleteResult`:**
  - **in use**: it sets `disabled_at` and returns `result: "disabled"` with the usage (no step-up, since that's reversible);
  - **free**: it deletes the item for good and returns `result: "deleted"`. No step-up: recorded in the activity log as `library.item_delete` (kind, item).
  - A disabled item is deleted for good by deleting it again once it's free. `POST …/{id}/enable` clears `disabled_at`.
- **A disabled item can't be used again** (409 `LIBRARY_ITEM_DISABLED`; `ensure_not_disabled`):
  - not copied into an exercise (`add_exercise_actor`, `add_exercise_threat_actor`, `add_exercise_inject`, `POST /ttx/{ttx_id}/tags`);
  - not assigned anew to a member, a domain or the organization (`validate_organization_tag_ids_belong_to_org`'s `already_assigned`: it can stay where it already is).
  - Editing it stays allowed.
- **UI** (`LibraryDeleteDialog`):
  - Before confirming, the dialog loads the usage. In use, it lists the impact and the button reads **Disable**; free, it warns that the delete is permanent and the button reads **Delete permanently**.
  - Exercise-level items keep the plain warning.
  - A disabled row shows `DisabledBadge` (Disabled · N uses) and `EnableButton`, and its Duplicate menu has no "to this exercise" option.
  - Pickers drop disabled items (`lib/libraryItems.ts`'s `enabledOnly`: `ActorLibraryPicker`, `ThreatActorsSection`, the inject form's senders). `TagAssignmentField` lists a disabled tag only where it was already assigned when the form opened.

## Who does what (every kind)
`lib/libraryLevels.ts`'s `libraryPermissions(withExercise)`, passed by `LibrarySection` to each kind:

| Module | TTX-Zone | My organization | This exercise |
|---|---|---|---|
| Admin (Program Manager) | Duplicate → to my organization | New, Edit, Duplicate → to my organization, Delete / Re-enable, ATT&CK upgrade | — |
| Creator (Exercise Planner) | Duplicate → to this exercise (scenarios: to a new exercise, or replace this one) | View (read-only form) + Duplicate → to this exercise (scenarios: likewise) | Edit / Delete; no Duplicate |

Copying the organization into itself only makes sense for the Program Manager in Admin. The ways back from Creator: an Exercise Planner who is also a **Program Manager of the organization** can **save an exercise's simulated actor to the organization's library** (`permissions.saveToOrganization`; the server already refuses anyone else, `require_library_manager`) — from Library → This exercise (`common/SaveToLibraryButton` on the row) and from the inject dialog's Source field ("Save to the organization's library" under the sender). The library actor is the same actor, no `_copy`, copied from the exercise (`lib/actorLibrary.ts`'s `toOrganizationLibrary`/`saveActorToOrganization`); the exercise's actor then becomes a copy of it (`origin = organization`), so it counts as a use and isn't offered again. In the Library that's a `PATCH` of the cast row; in the inject dialog the origin goes into the draft and the autosave keeps it (no cast write, so no `MSEL_STALE`). The same Program Manager can also **save a scenario's threat actor or an MSEL inject** to the organization's library from Library → This exercise (`SaveToLibraryButton`): as it is, no `_copy` (`lib/threatActors.ts`'s `fromExerciseThreatActor`, pinned to the MSEL's ATT&CK release; `lib/injectLibrary.ts`'s `fromExerciseInject`, in the exercise's content language, without its images and files). The MSEL isn't written — that would be an MSEL edit taking a READY MSEL back to DRAFT — so the exercise row keeps its origin, doesn't count as a use, and "already saved" is read from the library instead: the button hides while an organization item has `origin: exercise` + `origin_id` = that row. `DuplicateMenu` takes `showOrganization`/`showExercise` and renders nothing when neither applies; read-only forms (`ActorFormModal`, `InjectFormModal`, `TagFormModal`, `ThreatActorFormModal` `readOnly`) open from `common/ViewButton`.

## UI (shared by every kind)
- Routes: Creator → Library (`/creator/:ttxId/library[/kind]`, literal `/creator/library[/kind]`) and Admin → Library (`/admin/library[/kind]`). Tabs under the page title (`common/PageTabs`) list Simulated actors / Threat actors / Injects / Scenarios / Tags (tags last; `LIBRARY_KINDS`; routes generated from `LIBRARY_SUB_KINDS`, so a new kind gets its route). `LibrarySection kind=…` renders the kind.
- Level switch: segmented TTX-Zone | My organization | This exercise (the last only in Creator with an exercise in context) — `LibraryLevelSwitch` + `hooks/useLibraryLevelParam` on `?tab=`, `lib/libraryLevels.ts`, copy under `templates.levels.*`. Switching kind keeps the level.
- **Every library table looks the same** (cell rules: `frontend/CLAUDE.md` → Tables): a panel per level (title, description, count + the level's action), `LibraryFilterBar` (search + the kind's selects, in the URL via `hooks/useLibraryFilters`), then the table or `LibraryNoMatches` with Clear filters (`components/templates/LibraryFilters.tsx`). Filters: actors type/channel (+ origin); threat actors matrix/tactic (+ MITRE/unknown; search also matches technique ids — "T1486" lists who uses it); injects family/stage/audience (exercise: phase/kind); tags group (TTX-Zone) or origin.
- Row actions are icons, always in this order: the **primary** one first — **Edit** where the reader may change the item, **View** (`common/ViewButton`, read-only form or detail dialog) everywhere else, TTX-Zone rows included; names are plain text, never links (an exercise item edited elsewhere gets a pencil `common/IconLinkButton`) — then **Duplicate** (`common/DuplicateIcon`/`DuplicateMenu`, a `<details>` menu: to my organization / to this exercise), Edit, Re-enable (disabled organization items), Delete (an exercise's cast actor: disabled while an inject sends it; an organization item: see above). A duplicate to the organization gets the `_copy` suffix and **opens for editing right away** (the library switches to that level and opens the new row's form). "To this exercise" is a *use*, not a duplicate: no suffix.
- Forms show a read-only **"Copied from"** (`CopiedFrom`: level · original name) above the name, which carries its container as a fixed prefix (`ContainerNameInput`: "Organization ·"/"Exercise ·", the input's `aria-describedby`). Origin chips: `ActorOriginBadge` (TTX-Zone with a lock).

## Simulated actors
Files: `components/templates/`, `app/data/actor_catalog.py`, `actor_library_service.py`, `endpoints/actor_library.py`; tests `test_actor_library.py`, `ActorLibrary.test.tsx`.
- **Simulated actors are who is *not* playing** (the simulation cell voices them).
- TTX-Zone: `GET /actor-catalog`. Includes the other security teams of a large organization — `soc-local`, `soc-global`, `soc-business-unit`, `csirt-global`, `csirt-local`, and `cybersecurity-team-member` ("when the team isn't playing") — plus `dfir-provider` ("Incident response provider (retainer)"), `threat-intel-provider`, `bank`, `security-researcher`, `board-chair`. `insider` ("Employee") covers any non-playing staff member. SOCs usually escalate by **ticket**.
- Organization: `OrganizationActor`, `GET/POST/PATCH/DELETE /organizations/{organization_id}/actors`.
- Exercise = the **cast** (`MselSimulatedActor`, table name kept), owned by the exercise (`ttx_id`), not its MSEL; `ACT-NN` from `TTX.next_actor_number` (1 = never seeded). `GET/POST/PATCH/DELETE /ttx/{ttx_id}/actors[/{actor_id}]` (Planner-gated, no needs/MSEL condition; the list carries `in_use`; an actor an inject sends can't be removed, 409 `ACTOR_IN_USE`).
- `ensure_cast` seeds TTX-Zone's `default` actors on first use (Library or MSEL, once) and, when the MSEL is created, adds the actors of regulations the needs analysis names (NCCS) if missing. With an MSEL, a cast write is an MSEL edit (revision bump → an open MSEL page gets `MSEL_STALE`; past DRAFT it returns to DRAFT); the MSEL's whole-draft save writes the cast too.
- Fields: name, type, `description`, `channel` (usual delivery method — picking the actor in an inject prefills it; plain string column), `played_by` (exercise level only), origin fields. `ActorRead`'s newer fields default, so old snapshots load.
- The MSEL has no cast panel: the inject dialog's Source field adds a sender from the library (`ActorLibraryPicker`, copies into the draft, no suffix) or a new one.
- `DeliveryMethod` includes `ticket` and `security_tool` ("Cybersecurity tool": a SIEM/EDR alert or console) — labels in both locales and `msel_pdf_labels.py`.

## Threat actors
`ThreatActorLibrary`, `lib/threatActors.ts`; tests `test_threat_actor_library.py`, `ThreatActorLibrary.test.tsx`. ATT&CK rules: `docs/architecture/attack.md`.
- TTX-Zone = MITRE's live groups of the latest release (`GET /threat-actor-catalog`: id, name, associated groups, techniques), searchable by id/name/alias, read-only view (`ThreatActorFormModal readOnly`: techniques by tactic, MITRE's copyright). A copy of a group (to the organization or a scenario, `copyOfSystem`) starts with **no techniques**: the Planner ticks those the scenario uses in the picker, whose filters show the group's MITRE-documented ones (none ticked). Copies of organization or exercise actors keep theirs.
- Organization = `OrganizationThreatActor` (`GET/POST/PATCH/DELETE /organizations/{organization_id}/threat-actors`): a MITRE group copied and narrowed, or an unknown actor with or without techniques; pinned to its own `attack_version`; `mitre_group_id` fixed once copied. Upgrade banner `LibraryAttackUpgrade`.
- Exercise = the scenario's threat actors (read from the MSEL): duplicate to the organization, remove, edit on the MSEL page (`?tab=threats`). "To this exercise" from other levels adds a converted copy.

## Injects
`InjectLibrary`, `lib/injectLibrary.ts` (conversions); tests `LibrarySection.test.tsx`, `InjectLibrary.test.tsx`, `test_inject_catalog.py`, `test_inject_library.py`. Writing new catalog injects: `docs/features/inject-catalog-authoring.md`.
- **TTX-Zone**: `app/data/injects/catalog.json`, loaded and validated by `app/data/inject_catalog.py` (Pydantic, `lru_cache`: code format, actor ids, ATT&CK tactic/technique in the catalog's pinned release, framework ids, contingent → mandatory of the same families, variables). A broken catalog fails `test_inject_catalog.py`, never a request. `GET /inject-catalog` (any authenticated user) serves it with ATT&CK names. Codes `INJ-<FAM>-NN` / `INJ-<FAM>-CNN` (`FAMILY_CODES`), stable. `stage` proposes the MSEL phase and `capabilities` the objectives on copy; code, offset, phase, objectives and review status are never in a template. `within_minutes` is scenario time; `key_question` required for `executive`/`mixed`. Variables: system (`SYSTEM_VARIABLES`, no default) and scenario (`snake_case`, bilingual default in `variable_defaults`) — meant to be filled once per exercise, never substituted into a template. The page filters by family/stage/audience/search with the open inject in the URL (`?family=&stage=&audience=&q=&inject=`); `InjectTemplateDialog` shows it in full with `VariableText` marking `{variables}`. A few injects carry an illustration (`images`, `docs/features/inject-catalog-authoring.md` → Illustrations): `GET /inject-catalog` lists them (index, caption, size) and `GET /inject-catalog/{id}/images/{index}?lang=` serves the PNG (any authenticated user, inline, `nosniff`, cacheable: product content, not exercise data); the detail dialog previews them. Copying a TTX-Zone inject into an exercise (`POST /ttx/{id}/msel/injects` with `origin: system`) copies its illustrations as MSEL images in the copy's `language` (else the exercise's `content_language`, else English), re-encoded like any upload and captioned; past the MSEL's image limit they're left out, never blocking the copy. Duplicating to the organization doesn't carry them (organization injects have no images yet). Every inject table marks the rows that come with images or files (`common/InjectMediaMarks`: an image and a paperclip icon with the count, spoken label).
- **Organization**: `OrganizationInject` (one language, stated in `language` `en`|`es` like a scenario's — `NULL` only for injects saved before it existed, shown as "—"; template fields as columns/ARRAY/JSONB — `expected_actions` with scenario `within_minutes`, `attack` + `attack_version`, `variable_defaults`; the sender *described* — `actor_name`/`actor_type`/`actor_origin`/`actor_origin_id`; origin fields). `GET/POST/PATCH/DELETE /organizations/{organization_id}/injects` (`inject_library_service`; validates system inject/actor ids and ATT&CK in its release). Edit in `InjectFormModal` (Language select next to the title). A duplicate takes its language from where it comes from: a TTX-Zone inject in the language picked in `DuplicateMenu` (`languages`: one "To my organization · <language>" entry each), an organization one keeps its own. A new one starts in the UI language, shown and editable in that select.
- **Availability is not the reader's language**: the "Available in" column (`AvailableLanguages`) says which languages the content exists in — both for TTX-Zone (`SYSTEM_INJECT_LANGUAGES`; the catalog requires them), its one `language` for an organization inject. The text of a TTX-Zone row is read in the UI language.
- **Language when copying into an exercise**: nothing to fill in. MSEL injects have no language of their own (they follow the exercise's `content_language`); a TTX-Zone inject is copied in the exercise's language, whatever the UI's (`contentLanguage`, `fromSystemInject`); an organization inject in another language gets a non-blocking note in `InjectCopyDialog` (its text is adapted in the MSEL).
- **Exercise = the MSEL**: `POST /ttx/{ttx_id}/msel/injects` adds one copy — phase, objectives and time chosen in `InjectCopyDialog` (time relative to the phase), variables filled client-side, the key question appended to the facilitator notes, scenario → session minutes via `time_compression`; the server finds the sender in the cast by TTX-Zone id or name or adds it, converts ATT&CK onto the MSEL's release, and refuses past the limits (`MSEL_FULL`/`CAST_FULL`). `DELETE /ttx/{ttx_id}/msel/injects/{inject_id}` removes one. Both need an editable MSEL and count as an MSEL edit. `Inject.origin/origin_id/origin_name` record the source (`InjectRead` defaults them). Exercise rows duplicate to the organization (`fromExerciseInject`: session → scenario minutes, objectives' capabilities, stage from the phase's position); editing stays on the MSEL page — the edit icon links to `/creator/:ttxId/msel?tab=injects&inject=<id>`.

## Tags
`app/data/tag_catalog.py`, `organization_tag_service`, `ttx_tag_service`, endpoints `ttx_tags.py` + `organizations.py`; tests `test_ttx_tags.py`, `TagLibrary.test.tsx`.
- TTX-Zone: 35 bilingual tags in five groups, one colour per group (`SystemTagGroup`: threat = the inject families, audience, regulation, programme, people and domains), each with a "when to use it" line; `GET /tag-catalog`.
- Organization: `OrganizationTag` (`GET/POST/PATCH/DELETE /organizations/{organization_id}/tags`), applied to the organization (`PUT /organizations/{organization_id}/tags/apply`, full replace, Program Manager-only), to Program Manager and Planner grants (`MembershipTagAssignment`, keyed by membership id) and to allowed domains (`AllowedDomainTagAssignment`).
- Exercise: `TTXTag` owned by one exercise (`GET/POST/PATCH/DELETE /ttx/{ttx_id}/tags`, Planner-gated, in `DESIGN_ENDPOINTS`), applied to the exercise (`PUT /ttx/{ttx_id}/tags/apply`, `TTXTagAssignment`), its invitation tokens (`PUT /invitation-tokens/{token_id}/tags`) and planning team members (`TTXAccessTagAssignment`) — only its own tags (`validate_tag_ids_belong_to_ttx`, 404 otherwise).
- Origin fields set on create only (`UNKNOWN_SYSTEM_TAG` 422 for a bad TTX-Zone id); a duplicate gets `_copy`, the name shortened first to fit 24 characters (`asTagDuplicate`).
- Deleting an exercise tag deletes its assignment rows first (`delete_tag_assignments`); an organization tag still applied anywhere is disabled instead (see the top of this page). Join tables have plain FKs; the org cascade removes each exercise's tags (`delete_tags_for_ttx`) before the exercises.
- Name required, ≤ 24 characters (schemas and `maxLength`). Colours: curated `TagColor` palette (`--color-tag-*`, `lib/tagColors.ts`'s `TAG_COLOR_SWATCH_CLASS`), clear of severity/accent/cta/danger/success hues, plus opt-in `custom` with a `#RRGGBB` `custom_hex` (`validate_custom_hex`, no contrast guarantee).
- UI: `TagLibrary` (TTX-Zone grouped by group, Origin column via `ActorOriginBadge kind="tags"`, Delete through `LibraryDeleteDialog`) + `TagFormModal` (name, colour swatch, custom hex, preview chip, "Copied from"). `common/TagChip` truncates (full name in `title`).
- **Assigning stays in each entity's form**: `TagAssignmentField` (controlled checkbox list, full-set replace; staged until Save; ids of a tag deleted meanwhile dropped once the list loads) with a "Manage tags in the Library" link (`common.manageTags`) — Admin → Organization → `/admin/library/tags?tab=organization`, Creator → Exercise → `/creator/:ttxId/library/tags?tab=exercise`. A new exercise has no tags yet, so its create page shows no picker. Invitations' and the planning team's pickers read the active exercise's tags; Invitations' Edit button exists only to open the tag `Modal`.

## Formats and polls
`OrganizationInject` keeps an inject's `format` (`inject`, `discussion`, `poll`) and, for a poll, `poll_question`, `poll_options` and `poll_outcomes`: the form asks for them, the list marks a poll, saving one from an exercise keeps them, and copying it brings them to the MSEL as `POL-NN`, with no objectives or expected actions. `poll_impacts` stay behind: meters belong to each exercise, so a copied poll starts with none. The TTX-Zone catalog has no polls.
