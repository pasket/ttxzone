# Preferences and logout

## Preferences (`/account/settings/*`)
- Reachable **only** from the avatar dropdown (`Header`'s "Preferences" link). The dropdown is Preferences, **Create your own organization** (`/account/organizations/new`, `components/account/CreateOrganizationPage`: header without a module menu, like Preferences; `RequireFullAccess` but not `RequireModule`, so an account with no role reaches it — the Waiting Room links there too; on success `refresh()`, the new org becomes active and the page lands on `/admin`; see `docs/architecture/rbac-and-multi-org.md`), Log out. Not a module: absent from `MODULE_DEFS`/`getVisibleModules`/the Primary Menu. Components: `AccountSettingsLayout` (`components/layout/`) + `AccountSettingsGeneral`/`AccountSettingsDefaults`/`AccountSettingsSecurity`/`AccountSettingsPrivacy` (`components/account/`).
- Named **Preferences / Preferencias** in copy only (`nav.settings`, `account.settings.navTitle` *values*; keys, routes and components keep "settings") to avoid clashing with Admin's `/admin/settings` (Allowed Domains).
- A single nav column styled like `PrimaryNav` (216px, accent left border; a horizontal row below `lg:`): General / Default workspace (only when `hasContextChoices`) / Security / Privacy. "Preferences" is the `<nav>`'s accessible name, not a visible column. The active section comes from `useLocation().pathname.split('/').pop()`, **not** `useParams()` — these are literal child routes, there is no `:section` param.
- Outside `RequireFullAccess`/`AuthenticatedLayout` (only `RequireAuthenticated`) on purpose: a user held at the mandatory-TOTP gate must reach Security to enroll, and sees the full nav meanwhile; only leaving Preferences for a module stays blocked.
- **General**: language, read-only Email row (reuses `auth.login.emailLabel`), `AvatarPicker` (preset grid or upload — `POST /auth/avatar/preset`, `POST /auth/avatar/upload`, `DELETE /auth/avatar`), Light/Dark **Theme**. No editable display name.
  - Theme: `lib/themeStore.ts` (pure: `Theme`, `ThemeContext`, `readStoredTheme`/`applyTheme`/`persistTheme`) + `lib/ThemeContext.tsx` (`ThemeProvider`, wrapping the whole app outside `Router`/`AuthProvider` so it applies on login too) + `hooks/useTheme.ts`. **`localStorage`-only** (`ttx_theme`), no backend field — a per-device preference.
- **Default workspace**: see `docs/architecture/rbac-and-multi-org.md`.
- **Security**: MFA status pill (`account.settings.mfaActive`/`mfaInactive`, from `user.totp_enabled`), TOTP enroll/disable (`TotpEnrollment` — StrictMode `useRef` guard, see `frontend/CLAUDE.md`), `BackupCodesRegenerate` (step-up, `POST /auth/totp/backup-codes/regenerate`, codes revealed once via `BackupCodesReveal`), `ChangePassword` (three fields; client checks ≥ 8 chars and new === confirm before `POST /auth/password`), Active sessions (`ActiveSessions.tsx`, see `docs/architecture/session-policy.md`).
  - Backend `change_password()` (`auth_service`, `PasswordChangeRequest`) mirrors `totp_service.disable`'s re-auth: `verify_password` on the current password, reusing `INVALID_CREDENTIALS` on mismatch; ends every *other* session.
  - **8-character floor** (product decision): every password schema goes through `StrongPassword` (`app/core/password_policy.py`'s `PASSWORD_MIN_LENGTH` + the four character classes), mirrored by `lib/passwordPolicy.ts`. On top of it, the instance's own rules (Platform → Sign-in security, `security_policy_service`): a longer minimum (forms read it from `/instance/policy`'s or `/auth/me`'s `password_min_length`, `hooks/usePasswordPolicy`), no name/email, no reuse of the last N, a maximum age. Every password set goes through `check_new_password` + `set_password` (history, `password_changed_at`). They apply to newly set passwords; an expired one turns `/auth/me`'s `password_change_required` on with `password_change_reason: "expired"` (same `RequiredPasswordChange` screen, its own copy).
- **Privacy**:
  - **Leave {organization}** (`LeaveOrganization`, above the deletion; only where the active org — the ContextBar's — holds an org grant for the person): *Leave the organization…* loads `GET /organizations/{id}/leave-preview` and shows the Program Manager successor select (required, first candidate preselected, for the last one; optional with *Nobody* otherwise; no candidate → a link to delete the organization instead), each exercise seat that goes (a lead picks the new Lead Planner; the only Planner/Controller of one blocks the submit) and the org's name typed; `POST …/leave` (no step-up, recorded as `organization.leave`), a toast, `refresh()` (the switcher moves on). Player seats stay (a Player leaves an exercise through its Planners).
  - **Delete account**: self-service, irreversible account deletion — typed phrase `'delete my account'` (deliberately untranslated: the exact phrase is the friction), `DELETE /auth/me` (`deactivate_account`, step-up), then `/login`. If the account leads exercises, one select per exercise picks the successor Lead Planner (longest-standing member preselected; `GET /auth/me/lead-exercises`, `lead_successors` in the payload). The typed-confirmation modal pattern used elsewhere (organization delete, removing people) comes from here.

## Logout
`AuthContextValue.logout` = `POST /auth/logout` then `refresh()` (the normal snapshot path), from the avatar dropdown. Backend `clear_auth_cookies` mirrors `set_auth_cookies`'s exact attributes — a mismatched `path`/`secure`/`samesite` silently fails to clear a cookie in some browsers.
