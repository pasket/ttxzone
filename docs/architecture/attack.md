# MITRE ATT&CK data

## Principles
- Enterprise + ICS tactics, techniques, sub-techniques and **groups** (threat actors). Names are English only, as MITRE publishes them.
- The catalog is **read-only and lives in code**: one JSON per domain and release. The app never downloads anything at runtime.
- Every use stores **only ids plus the release** they belong to. Names are always read from that release's file, which is never deleted.
- Moving between releases is **always explicit** and **always reports** what changed. Nothing is rewritten in the background.
- Current release: **v19.2**. MITRE's copyright line ("Copyright 2015-2026, The MITRE Corporation. MITRE ATT&CK and ATT&CK are registered trademarks of The MITRE Corporation.") is shown wherever ATT&CK data appears (Scenario, Library, PDFs).

## What is imported
- **Tactic**: id (`TA0001`) and name, in matrix order.
- **Technique**: id (`T1566`, `T1566.001`), name, the tactics it serves, its parent if it's a sub-technique, deprecated flag.
- **Group**: id (`G0007`), MITRE name, associated groups (aliases), the techniques its `uses` relationships name (no tactic), deprecated flag. Groups present in both domains (e.g. G0034) are merged, with the techniques of both.
- **Revocations**: technique → replacement and group → replacement maps; chains (A → B → C) are followed to the live one.
- Source: `github.com/mitre-attack/attack-stix-data` (official STIX 2.1); each file records the source URL and SHA-256.

**Deliberately not imported:** technique and group descriptions (they carry citations and weigh a lot; each item links to its versioned page on attack.mitre.org instead), campaigns, software/malware, mitigations, data sources, and the Mobile matrix.

## Limitations to keep in mind
- **Going to an older release** (copying from v20 into a v19.2 MSEL) has no replacements to apply: it only removes what the old release lacks. Correct, but newer techniques can be lost — prefer upgrading the MSEL.
- **MITRE decides replacements.** A revoked technique becomes the one MITRE names, whose scope may differ slightly; review the affected injects after an upgrade.
- **Group profiles are documented uses**, not everything a group can do — which is why a technique outside an actor's profile is only a warning (M20).
- **When MITRE moves a technique to another tactic**, an inject moves it to its first valid tactic, which may not be the one the designer would pick.
- **The TTX-Zone inject catalog is reviewed by hand** on every import; `test_the_catalog_is_written_against_the_latest_attack_release` only forces the review, it doesn't do it.
- **A shipped release is never deleted** while any MSEL, snapshot or library item uses it — in practice, never.
- Test fixture `next_release` (`backend/tests/conftest.py`) fakes a v99.0 (a revoked, a deprecated and a re-tacticked technique, a new and a removed group) to exercise every conversion path.

## Catalog files and loader
- One compact JSON per domain and release under `app/data/attack/` (tactics in matrix order, techniques with `parent`/`deprecated`, revoked → replacement map, source URL + SHA-256, MITRE's copyright, and the release's **groups** — `intrusion-set`: G id, name, associated groups, `uses` techniques, revoked-group map). Generated by `scripts/import_attack.py` (stdlib; `--from-dir` reads an already-downloaded `index.json` + bundles).
- `attack_catalog.py`: `ATTACK_VERSIONS` oldest first — never remove a release, pinned MSELs read their names from it. `load_groups(version)` merges both domains; `group_replacement` follows revocations. `latest_attack_version()` / `is_shipped()` read `ATTACK_VERSIONS` at call time (so the `next_release` fixture can add v99.0).
- Importing a release: steps in `scripts/import_attack.py`'s docstring (run inside the backend container); then review `catalog.json` — `test_the_catalog_is_written_against_the_latest_attack_release` fails until its `attack_version` is bumped. No DB migration needed.

## In the MSEL
- Every MSEL pins `attack_version` (the latest at creation). Names are resolved from the pinned release at read time and so frozen into the READY snapshot.
- **Threat actors** (`MselThreatActor`, 1–5 per scenario, `THR-NN` via `msel.next_threat_actor_number`): a MITRE group (`mitre_group_id`) or an unknown actor, each with a technique **profile** (JSONB (domain, technique) pairs, no tactic; unknown actors may have none), notes on its role/collaboration, the copy origin and `modified_at` (stamped only when a save or an upgrade really changes it).
- **Inject attribution**: `attack_attribution` = `threat_actor` | `noise` (unrelated activity, coincidences, false positives) | null (no ATT&CK), plus `threat_actor_id`; techniques relational in `inject_attack_technique` (domain, tactic, technique). `MselRead.attack_techniques` is **derived** from the injects.
- **Tolerant save**: an attribution to a removed actor loses the actor (warning); techniques with no attribution are dropped. A save accepts only live techniques of the pinned release (injects: under one of their own tactics; profiles: any tactic) and live groups — 422 `UNKNOWN_ATTACK_TECHNIQUE` / `UNKNOWN_ATTACK_GROUP`.
- **Upgrade** (`POST …/msel/attack-upgrade`, `upgrade_attack`): revoked techniques and groups → MITRE's replacement, deprecated/vanished removed (a vanished group leaves an unknown actor with its name), all reported; reopens the MSEL like an edit; the old snapshot keeps its release.
- Removing an actor (`DELETE …/msel/threat-actors/{id}`) leaves its injects' techniques attributed to no one. Copying a library inject takes `attack_attribution`/`threat_actor_id` (default: the scenario's first actor).
- Validation: M18 `ATTRIBUTION_WITHOUT_TECHNIQUE`, M19 `ATTRIBUTION_WITHOUT_ACTOR`, M20 `TECHNIQUE_OFF_ACTOR_PROFILE` (a warning — profiles are documented uses only), M21 `THREAT_ACTOR_WITHOUT_INJECTS` (shown in Injects, where it can be fixed); a nameless threat actor is `MSEL_INCOMPLETE`.
- Migrations: `9c2a19211b1b` moved the old id arrays (and snapshot payloads) to versioned refs under v19.2; `88eb69c0dc18` turned the old free-text threat profile and hand-picked technique list into one unknown actor THR-01 per MSEL, attributing its injects to it; `ee7b7edf43f8` added `modified_at`.

## Crossing releases (`app/services/attack_conversion.py`)
One rule everywhere (`convert_refs` / `convert_profile`): revoked → MITRE's replacement, deprecated/missing removed, a group the target release lacks dropped so the actor stays as an unknown one — all reported as `AttackConversionRead` ("2 replaced: T1566 → T1566.001…, 1 removed: T1490"). Used by:
- the MSEL upgrade;
- every copy from a library into an MSEL: `POST …/msel/injects` → `{msel, conversion}`, `POST …/msel/threat-actors` → `{actor, conversion}`, and `POST /attack/{version}/threat-actor` (a no-write conversion the Threat actors tab's picker runs before adding to its draft);
- **organization libraries**, which keep their own `attack_version` per item until `POST /organizations/{id}/threat-actors/attack-upgrade` / `…/injects/attack-upgrade` moves them all to the latest (`LibraryAttackUpgrade` banner: "N items use an older ATT&CK release · Update to vX").

## UI
- **MSEL → Threat actors tab** (`ThreatActorsSection`): one full-width row per actor (a list, not a grid: 1 to 5 read the same and the techniques unfold across the panel without stretching a neighbour) — code, name, MITRE id link or "Unknown actor" with the also-known-as names on one truncated line (all on hover), notes clamped to two lines; stats and Edit/Remove on the right — no origin badge, the row is the exercise's own copy; an actor's techniques are **the scenario's techniques** — those this exercise uses, not everything MITRE documents: with none, the row says "No techniques chosen yet" plus "Choose techniques…" (`ThreatActorTechniquesPicker`: the `AttackPicker` on MITRE's documented list as filters, nothing ticked); with some, plain stats "N of M techniques" (M = MITRE's documented count, `/threat-actor-catalog`; an unknown actor "N techniques") · "K exercised" (accent when > 0) · "J injects", and "Show the scenario's techniques" unfolds them by tactic, those its injects use marked ✓, with "Edit techniques…"). The tab is optional (its copy says so): an MSEL with no threat actors is complete. "Add from the library" (MITRE groups or the organization's, searchable; techniques the MSEL's release lacks are left out) and "New unknown actor", edited in `ThreatActorFormModal` (level exercise; its form shows "Copied from" plus "Not modified since it was copied" or "Last modified …" — organization actors compare `updated_at` with `created_at`), removed with Undo. Then the pinned release and upgrade banner (`AttackRelease`). The inject wizard's "no threat actors" note and Library → Threat actors → This exercise link to `?tab=threats`.
- **Inject wizard, step 4** (`InjectAttackField`): No ATT&CK | Threat actor | Noise, the actor select, technique chips under a "MITRE ATT&CK techniques" heading ("(optional)" for noise). A technique outside the actor's scenario techniques is flagged "not among X's scenario techniques" (why on hover) and one click from "Add to the scenario's techniques" (`onDraftPatch` updates the scenario's actor).
- **`AttackPicker`** modal: matrix → tactic → techniques with collapsible sub-techniques; search across the matrix lists a technique once per tactic; staged until Apply; ≤ 20 techniques. With `profile` it opens on the actor with two filters, both on at first (no ★ marks): "Only X's tactics" and "Only X's techniques" (a sub-technique whose parent isn't in the profile gets its own row, full name); with techniques-only and every tactic, a tactic with none is disabled (count shown); the open tactic always moves to one with something to show. `keyOf` lets a profile pick techniques tactic-free. The help line says MITRE only records documented uses, that an off-profile technique is flagged for review (add it to the profile there) or the actor can be adapted in the Library. `ThreatActorFormModal` (Library and the MSEL's Threat actors tab) passes the MITRE group's documented techniques (`GET /threat-actor-catalog`) as `profile`, with its own `profileHelp`: the filters show MITRE's list, the ticks are the actor's own (a MITRE copy starts with none, `copyOfSystem`); an unknown actor gets no filters. An inject's picker still filters on the scenario actor's own profile (none: no filters, nothing flagged off-profile).
- Injects tab: ATT&CK filter (none / actor / noise) and an upgrade banner when a newer release ships; MITRE's copyright line wherever ATT&CK data appears. Coverage has no ATT&CK list; each inject and the PDFs list their own techniques.
- PDFs: the full MSEL and facilitator guide show actors and attribution; SitMan and inject cards never (it would reveal the answers).
- Library → Threat actors (TTX-Zone = MITRE groups of the latest release; organization; exercise): `docs/features/library.md`.
