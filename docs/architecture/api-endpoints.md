# API endpoint catalog

New endpoints go in `app/api/v1/endpoints/<router>.py` and are included in `app/api/v1/api.py`'s `api_router`. All paths below are under `/api/v1`. Regenerate this list from the code when in doubt (the `@router.<method>` decorators); the guards are summarized per group — the code is authoritative. Step-up endpoints: see `docs/architecture/session-policy.md`.

## `health.py`
`GET /health`, `GET /health/db`.

## `auth.py`
- Sign-in: `POST /auth/login` (with `mfa_required`, also `mfa_methods` and `mfa_preferred`; 429 `LOGIN_THROTTLED` after too many failures, `docs/architecture/session-policy.md`), `POST /auth/login/challenge` (a pending challenge's methods, for the page single sign-on hands the token to), `POST /auth/login/email-code` (emails a code for the pending challenge), `POST /auth/login/verify-totp` (`method`: `totp` | `email` | `backup_code`; none = TOTP, then a backup code), `POST /auth/step-up` (`method: "email"` for an email code; 409 `SSO_STEP_UP_REQUIRED` for an account with no TOTP, email code or password), `POST /auth/step-up/email-code`, `POST /auth/logout`.
- Email links (`account_email_service`, `docs/architecture/email.md#account-links`): `POST /auth/password/forgot` (public, 202 whether or not the account exists; 409 `ACCOUNT_EMAIL_UNAVAILABLE` when the deployment sends no email or lacks `PUBLIC_BASE_URL`), `POST /auth/password/reset` (public: `token` + `new_password`, signs every session out, opens none), `POST /auth/email/verify` (public: spends a confirmation link from any browser), `POST /auth/email/verification` (session + CSRF: a new confirmation link, 429 `EMAIL_VERIFICATION_RATE_LIMITED` within a minute of the last). A spent, expired, withdrawn or foreign link is 400 `ACCOUNT_LINK_INVALID`. `GET /instance/policy`'s `password_reset_available` tells the sign-in page whether to offer "Forgot your password?".
- `POST /auth/register` — a bare, org-less account (`register_bare_account`, `BareRegisterRequest`) for someone arriving with an invitation code; distinct from org signup (`POST /organizations`). Every account-creating route (this one, `POST /organizations`, token redemption with `account`) takes `accepted_legal` (`docs/features/legal-documents.md`).
- `GET /auth/me` — the user plus `is_program_manager`/`is_planner` (held in *any* org, via `user_is_org_planner`/`user_is_org_program_manager`; only for the global MFA gate), `is_instance_admin`/`is_last_instance_admin`/`can_found_organization` (`docs/features/instance-tenancy.md`), `legal_acceptance_pending` (`docs/features/legal-documents.md`), `default_organization_id`/`default_role`/`default_ttx_id`, `has_password`/`sso_linked`/`sso_provider` (`docs/architecture/sso.md`), `session` (`SessionInfo`, with `mfa_source`).
- `DELETE /auth/me` — self-service deletion (`deactivate_account`, typed phrase, `lead_successors`; clears an instance administrator grant); `GET /auth/me/lead-exercises`.
- Sessions: `GET /auth/sessions`, `DELETE /auth/sessions` (all but current), `DELETE /auth/sessions/{session_id}`.
- Defaults: `PUT /auth/default-context` (org + role + exercise, validated by `organization_service.set_default_context`); `PATCH /auth/default-organization` (unused by the UI; 404 for an org the user doesn't belong to; clears role/exercise when the org changes).
- TOTP: `POST /auth/totp/enroll`, `…/enroll/confirm`, `…/disable`, `…/backup-codes/regenerate` (allowed even mid mandatory-MFA lock — it doesn't weaken the second factor). Code by email as a second factor: `POST /auth/mfa/email/enable` (emails the code) + `…/enable/confirm`, `DELETE /auth/mfa/email` (step-up), `PUT /auth/mfa/preferred` (`totp` | `email`, only among those enrolled). `POST /auth/password`.
- Avatar: `POST /auth/avatar/preset`, `POST /auth/avatar/upload`, `DELETE /auth/avatar`.


## `auth_oidc.py`
Single sign-on (`docs/architecture/sso.md`). Public: `GET /auth/oidc/config` (`{enabled, display_name, provider_kind}`), `GET /auth/oidc/start?return_to=` (302 to the provider), `GET /auth/oidc/callback` (302 into the SPA; failures as `?sso_error=SSO_<REASON>`). Signed in, CSRF: `POST /auth/oidc/step-up` (`{return_to}` → `{authorize_url}`; 409 `SSO_NOT_LINKED`), `POST /auth/oidc/link` (step-up; 409 `SSO_ALREADY_LINKED`), `DELETE /auth/oidc/link` (step-up; 409 `SSO_UNLINK_NEEDS_PASSWORD`, 404 `SSO_NOT_LINKED`). 404 `SSO_UNAVAILABLE` / 502 `SSO_PROVIDER_UNREACHABLE` on the POSTs.
## `organizations.py` (all but signup and `/mine` (`GET`/`POST`) guarded by `require_program_manager_of`; `planner-overview` by `require_planner`; tag writes by `require_library_manager` (Program Managers), tag list by `require_library_reader` (+ org Planners))
- `POST /organizations` (signup: new account + org), `GET /organizations/mine` (`list_user_organizations`, any authenticated user), `POST /organizations/mine` (a signed-in account founds an org: `create_organization_for_user`, CSRF, recorded as `organization.create`, work domain, `ORG_LIMIT_REACHED` cap). Both refused by the tenancy rule first (`TENANCY_*`, 403).
- Newcomers: `GET …/domain-accounts` (active accounts from the org's allowed domains with no grant in it; empty in `open` tenancy).
- Profile: `GET`/`PATCH`/`DELETE /organizations/{organization_id}`, `POST`/`DELETE …/logo`.
- People (Admin → Users and roles): `GET …/members` (one row per person, all their grants, `disabled`, `role_counts`; `q`/`sort_by`/`sort_dir`/`role`/`status` (`active`/`disabled`)/`limit`/`offset`), `GET …/members/{user_id}/exercises` (what a revoke or removal touches), `PUT …/members/{user_id}/tags` (same tags on every grant), `DELETE …/members/{user_id}` (`deleted`, or `disabled` while still on exercises), `POST …/members/{user_id}/enable`. Leaving oneself (any member, Preferences → Privacy): `GET …/leave-preview` (Program Manager hand-over candidates, the exercise seats that go, `blocked` where the only Planner/Controller, lead candidates), `POST …/leave` (`{confirmation: org name, program_manager_successor_id?, lead_successors}`; step-up; 409 `PROGRAM_MANAGER_SUCCESSOR_REQUIRED`/`LEAD_SUCCESSOR_REQUIRED`/`ONLY_PLANNER_OR_CONTROLLER`, 400 `INVALID_PROGRAM_MANAGER_SUCCESSOR`/`CONFIRMATION_MISMATCH`). Revoking Planner/Observer/Evaluator cascades to the org's exercises. Per role: `GET`/`POST …/planners|observers|evaluators`, `DELETE …/{role}/{user_id}`, `PUT …/{role}/{user_id}/tags` (one route factory, `_register_member_routes`); `GET`/`POST …/program-managers`, `DELETE …/program-managers/{user_id}` (never the last), `PUT …/program-managers/{user_id}/tags`.
- Allowed domains: `GET`/`POST …/allowed-domains`, `PATCH`/`DELETE …/allowed-domains/{domain_id}`, `PUT …/allowed-domains/{domain_id}/tags`.
- Tags: `GET`/`POST …/tags`, `PATCH`/`DELETE …/tags/{tag_id}`, `GET …/tags/{tag_id}/usage`, `POST …/tags/{tag_id}/enable`, `PUT …/tags/apply`.
- Dashboards: `GET …/dashboard`, `GET …/planner-overview`.

- Instance administrator only (`require_instance_admin`, TOTP mandatory; writes CSRF): `GET`/`PUT /instance/settings` (PUT with step-up; 409 `TENANCY_PINNED_BY_ENV` when `TENANCY_MODE` is set), `GET`/`PUT /instance/security-policy` (password rules + second-factor mandate per role, `accounts_without_totp` per role; PUT with step-up, recorded as `security_policy.update`), `GET`/`POST /instance/free-email-domains`, `PUT …/free-email-domains/{domain}` (`{active}`, built-in only), `DELETE …/free-email-domains/{domain}` (added only; 409 `FREE_EMAIL_DOMAIN_BUILTIN`) — the list of domains that can't found their own organization under `open` (`applies`); writes with step-up, 409 `FREE_EMAIL_DOMAIN_EXISTS`, 404 `FREE_EMAIL_DOMAIN_NOT_FOUND`, `GET`/`POST /instance/organizations` (an existing account founds it; 404 `USER_NOT_FOUND`, 409 `TENANCY_SINGLE_EXISTS`/`TENANCY_ORG_LIMIT`), `PATCH`/`DELETE /instance/organizations/{id}` (domain; full cascade delete with step-up, the name typed in the UI), `GET`/`POST /instance/organizations/{id}/program-managers`, `DELETE …/program-managers/{user_id}` (409 `LAST_PROGRAM_MANAGER`; a suspended account 409 `ACCOUNT_SUSPENDED` here and on create), `GET /instance/accounts` (`q`/`limit`/`offset`: every active account with its organizations, roles, `disabled`, `sole_program_manager`), `POST /instance/accounts` (`{email, full_name}` → `{user_id, temporary_password}`, once; step-up; 409 `EMAIL_ALREADY_REGISTERED`), `POST /instance/accounts/{user_id}/suspend` (`confirmation` = the account's email; 409 `CANNOT_SUSPEND_YOURSELF`/`LAST_INSTANCE_ADMIN`), `POST …/accounts/{user_id}/reactivate`, `GET /instance/accounts/{user_id}` (one account: organizations, exercises with the roles held, sessions, backup codes, `dependencies`, `is_self`), `PATCH /instance/accounts/{user_id}` (`full_name`/`email`; 409 `EMAIL_ALREADY_REGISTERED`), `POST …/accounts/{user_id}/reset-password` (→ `temporary_password`, once; step-up), `POST …/reset-two-factor` and `POST …/end-sessions` (step-up), `DELETE /instance/accounts/{user_id}` (`{confirmation}` = the email; step-up; 409 `ACCOUNT_HAS_DEPENDENCIES`/`REVOKE_INSTANCE_ADMIN_FIRST`) — none on your own account (409 `CANNOT_MANAGE_YOURSELF`), `POST /instance/accounts/bulk` (`action` = `suspend`/`reactivate`/`end_sessions`/`delete`, up to 100 `user_ids`, `confirmation` = their number for suspend/delete; step-up; → `done`, `skipped` and each account's `code`, null when done), `GET /instance/admins` (active administrators, suspended ones marked, + `web_grants_enabled`), `POST /instance/admins` (`{user_id, confirmation}` = the account's email; 409 `ALREADY_INSTANCE_ADMIN`/`ACCOUNT_SUSPENDED`/`INSTANCE_ADMIN_WEB_GRANTS_DISABLED`), `DELETE /instance/admins/{user_id}` (yourself included; 409 `LAST_INSTANCE_ADMIN`/`NOT_INSTANCE_ADMIN`/`INSTANCE_ADMIN_WEB_GRANTS_DISABLED`), `GET /instance/audit` (the activity log, `limit`/`offset`/`action`/`q`/`sort_dir`, newest first; read-only), `GET /instance/audit/export` (`format=jsonl|csv` + the same filters, oldest first; step-up; recorded), `GET`/`PUT`/`DELETE /instance/audit/webhook` (forwarding to a SIEM: URL, enabled, optional Authorization header never returned, signing secret, delivery state; PUT and DELETE with step-up; 422 `AUDIT_WEBHOOK_URL_INVALID`), `POST …/webhook/rotate-secret` (step-up), `POST …/webhook/test` (404 `AUDIT_WEBHOOK_NOT_CONFIGURED`), `GET /instance/audit/retention` (`{days, log_file_max_mb, log_file_backups}`: the activity log's fixed 90 days and the log files' cap from `.env`; read-only). `GET /instance/organizations` and `GET /instance/accounts` take `q`, `sort_by` (`created_at`/`name`, accounts also `last_login`), `sort_dir`, `limit`/`offset` (both answer `total`); accounts also the combined filters `status` (`all`/`active`/`suspended`), `organization` (an id or `none`), `role` (an organization role, held there or anywhere) and `instance_admin` (`true`/`false`). Step-up on PUT settings, free email domain changes, DELETE organization, creating an account, suspend, reactivate and granting / revoking administrators only. Each write here (and publishing a legal document, exporting acceptances) is recorded in the activity log.

## `instance_email.py` (outgoing email; `docs/architecture/email.md`)
- Instance administrator only (`require_instance_admin`, TOTP mandatory; writes CSRF): `GET /instance/email` (the effective configuration without any secret: `active`, `pinned_by_env`, `allow_insecure`, sender, server, `has_password`, `password_readable`, outbox counts and last error), `PUT /instance/email` (step-up; `smtp_password` omitted keeps, `""` removes; 409 `EMAIL_PINNED_BY_ENV`, 422 `EMAIL_SMTP_HOST_INVALID`/`EMAIL_SMTP_PORT_NOT_ALLOWED`/`EMAIL_SMTP_INSECURE_NOT_ALLOWED`/`EMAIL_FROM_INVALID`/`EMAIL_REPLY_TO_INVALID`/`EMAIL_FROM_NAME_INVALID`), `DELETE /instance/email` (step-up; 404 `EMAIL_NOT_CONFIGURED`, 409 when pinned), `POST /instance/email/test` (`{to?}`, the administrator's own address by default; step-up; sends now, outside the queue → `{ok, to, error}`; 409 `EMAIL_NOT_CONFIGURED`, 429 `EMAIL_TEST_RATE_LIMITED` past 5 a minute), `GET /instance/email/outbox` (`status`/`limit`/`offset`, newest first; metadata only, never the content; `retention_days`), `GET`/`PUT /instance/email/reconfirmation` (`{days}`: 30–730 or null = off; `pinned_by_env`, `grace_days`; PUT step-up, 409 `EMAIL_RECONFIRMATION_PINNED_BY_ENV`). Each write and test is recorded in the activity log.
- Same guards, `instance_oidc.py`: `GET /instance/oidc` (the effective single sign-on configuration without the secret: `active`, `pinned_by_env`, `redirect_uri`, provider, `has_client_secret`, `client_secret_readable`, `linked_accounts`), `PUT /instance/oidc` (step-up; `client_secret` omitted keeps it; 409 `SSO_PINNED_BY_ENV`/`SSO_PUBLIC_URL_MISSING`, 422 `SSO_TENANT_ID_INVALID`/`SSO_ISSUER_URL_INVALID`/`SSO_CLIENT_ID_REQUIRED`/`SSO_CLIENT_SECRET_REQUIRED`), `DELETE /instance/oidc` (step-up; 404 `SSO_NOT_CONFIGURED`), `POST /instance/oidc/test` (step-up; fetches metadata and keys → `{ok, error, detail}`). Each write and test is recorded in the activity log.
## AI assistant (`docs/features/ai-assistant.md`)
- `instance_assistant.py`, instance administrator only (`require_instance_admin`, TOTP mandatory; writes CSRF): `GET /instance/assistant` (`enabled`, `pinned_by_env`, `disclaimer_version`, `active_tokens`), `PUT /instance/assistant` (step-up; 409 `ASSISTANT_PINNED_BY_ENV` when `ASSISTANT_ENABLED` is set), `GET /instance/assistant/calls?user_id=&limit=` (the last tool calls, at most 100, with who, token name and prefix, tool, exercise and organization, outcome, duration; and `callers` for the filter). `GET /instance/policy` carries `assistant_enabled`.
- `auth_tokens.py`, the caller's own personal access tokens, with the session cookie: `GET /auth/tokens` (not revoked, newest first, never the secret; with `enabled`, `disclaimer_version`, `max_active`, `expiry_days_choices`), `POST /auth/tokens` (CSRF + step-up; `{name, expires_in_days: 7|30|90, acknowledge, disclaimer_version}`; 409 `ASSISTANT_DISABLED` / `ASSISTANT_TOKEN_LIMIT`, 400 `ASSISTANT_DISCLAIMER_REQUIRED`; returns the secret once), `DELETE /auth/tokens/{token_id}` (CSRF; 404 `ASSISTANT_TOKEN_NOT_FOUND`).
- `mcp.py`: `POST /mcp`, authenticated **only** by `Authorization: Bearer ttxz_…` (never the cookie; a token authenticates nothing else). JSON-RPC 2.0 outside the `{"success": false}` envelope: 401 with `WWW-Authenticate: Bearer` for a bad token, 403 for a blocked account, a disabled assistant or a foreign `Origin`, 400 for malformed JSON-RPC or an unsupported `MCP-Protocol-Version`. `GET`/`PUT`/`PATCH`/`DELETE /mcp`: 405 `Allow: POST`.
- `ttx_assistant.py` (a Planner or the Lead Evaluator; a Program Manager reads the list; CSRF on writes, the caller's own proposals only): `GET /ttx/{ttx_id}/assistant/proposals?status=pending|accepted|discarded&target=need|objective|inject|aar_text|aar_objective|aar_action`, `POST /ttx/{ttx_id}/assistant/proposals/{proposal_id}/applied` (`{row_id}`), `POST /ttx/{ttx_id}/assistant/proposals/{proposal_id}/discard`. In `DESIGN_ENDPOINTS`; refused on an archived exercise.

## `legal.py` (the deployment's legal documents; `docs/features/legal-documents.md`)
- Public: `GET /legal`, `GET /legal/{kind}?lang=`. `POST /auth/legal/accept` (CSRF), `GET /auth/legal/acceptances` (the caller's). While an account has documents to accept, every other route answers 403 `LEGAL_ACCEPTANCE_REQUIRED` except `/auth/…`, `/legal…` and `/instance/legal…` (`get_current_user`).

## `ttx.py`
- `POST /ttx` (Planner of the body's `organization_id`; optional `content_language`, else the request's locale), `GET /ttx` (exercises visible to the caller), `PATCH /ttx/{ttx_id}` (name, description, optional `content_language`: a supported locale, left out kept), `POST`/`DELETE /ttx/{ttx_id}/image`, `PUT /ttx/{ttx_id}/tags/apply`, `GET /ttx/{ttx_id}/dashboard`, `GET /ttx/{ttx_id}/attention` (Planner; a Program Manager reads: how many validation issues keep the needs analysis, the MSEL and the session plan from moving on, `null` for one not opened yet -- it opens nothing; the Creator menu's counts).
- `POST /ttx/{ttx_id}/duplicate` — a new exercise with this one's design and team, body `{name, organization_id}` (the source's organization, else 404): a Planner of the exercise (`RequiresOrgAndTTXAccess(PLANNER)`, in `DESIGN_ENDPOINTS`) who is also a Planner of the organization (`require_planner`). 201 `{ttx, skipped_members}`; 422 `TTX_DUPLICATE_FAILED` (see `docs/features/creator-exercise.md`).
- `POST /ttx/{ttx_id}/archive`, `POST /ttx/{ttx_id}/unarchive` — read-only and out of the default lists, or back: the same people as the delete (Lead Planner, Program Manager; 403 `TTX_ARCHIVE_FORBIDDEN`), guarded in the endpoint; archiving refused while a session is live or paused (409 `RUN_IN_PROGRESS`). `TTXRead.archived_at`; `GET /ttx?archived=true|false` filters (left out: all). Every other write on an archived exercise: 409 `TTX_ARCHIVED` (see `docs/architecture/rbac-and-multi-org.md`).
- `DELETE /ttx/{ttx_id}` — delete the exercise for good: its Lead Planner or a Program Manager of its organization, body `{confirmation}` (its name), no step-up, recorded as `exercise.delete` (see `docs/features/creator-exercise.md`).
- `DELETE /ttx/{ttx_id}/access` — leave an exercise; no role guard (only ever removes the caller's own row; `?lead_successor_id=` for the Lead Planner). A Player gets 403 `LEAVE_NEEDS_APPROVAL`: they ask instead (below).
- Invitations: `POST`/`GET /ttx/{ttx_id}/invitation-tokens`; `GET /ttx/{ttx_id}/access-requests`, `POST …/access-requests/{request_id}/approve`, `…/reject`.
- Players (Creator → Players → Confirmed, Planner/design): `GET /ttx/{ttx_id}/players`, `DELETE /ttx/{ttx_id}/players/{user_id}` (`PLAYER` rows only, 404 `PLAYER_NOT_FOUND`; closes a pending leave request as approved).
- Leave requests (`TTXLeaveRequest`, `ttx_leave_request_service`): `POST /ttx/{ttx_id}/leave-request` `{reason?}` (the caller's own Player row, no role guard; 404 `PLAYER_NOT_FOUND`, 409 `LEAVE_REQUEST_PENDING`); Planner/design: `GET /ttx/{ttx_id}/leave-requests` (pending, of people still Players), `POST …/leave-requests/{request_id}/approve` (removes the Player) and `…/reject` (404 `LEAVE_REQUEST_NOT_FOUND`, 409 `LEAVE_REQUEST_ALREADY_DECIDED`); `GET /leave-requests/me` (the caller's pending ones).
- Planning and control team: `GET`/`POST /ttx/{ttx_id}/planning-team`, `GET …/planning-team/candidates`, `PUT …/planning-team/lead`, `PUT …/planning-team/{user_id}/functions` (plans/controls/facilitates), `DELETE …/planning-team/{user_id}`, `PUT …/planning-team/{user_id}/tags`. `GET /ttx` items carry the caller's `plans`/`controls`/`facilitates`; its `role` filter takes `planner`/`controller`/`facilitator`/`evaluator`/`observer`/`player`.
- Everything exercise-scoped here is `RequiresOrgAndTTXAccess(RoleEnum.PLANNER)` unless stated.

## `after_action.py` (`docs/features/after-action.md`)
- `GET`/`POST`/`PUT /ttx/{ttx_id}/aar` (read: Planners, Lead Evaluator, Controllers, Program Managers; write: Planners and Lead Evaluator — 403 `TTX_ACCESS_DENIED` before the body; `RUN_NOT_STARTED`, `AAR_EXISTS`, `AAR_STALE`), `GET …/aar/preview` (readers; before the report exists: `session_started`, `can_edit` and the objectives it will cover), `POST …/aar/run` (authors; `{run_id, revision}`: write it from another session, keeping the text; `AAR_STALE`, `RUN_NOT_FOUND`, `AAR_OBJECTIVES_IN_USE`), `POST …/aar/transitions` (`{to}`, recorded as `exercise.aar_final`/`aar_reopened`), `PATCH …/aar/actions/{code}` (status, note, due date, and the re-test link when `retest_ttx_id`/`retest_objective_id` are sent — null clears; never reopens; allowed on an archived exercise; 422 `RETEST_INVALID_EXERCISE` / `RETEST_INVALID_OBJECTIVE`), `GET …/aar/retest-candidates` (authors: the organization's later exercises with their objectives — code, name and objective titles only), `GET …/aar/export.pdf?lang=`.
- `GET /ttx/{ttx_id}/retests` (Planners, Controllers, Evaluators; Program Managers read): the improvement actions of earlier exercises this one re-tests.
- `GET /organizations/{organization_id}/improvement-plan?status=&overdue=&retest=linked|unlinked&q=&limit=&offset=` (Program Manager): every improvement action of the organization's exercises, soonest due first, with `open` and `overdue` counts; each row's `id` and `retest`. `GET …/improvement-plan/{action_id}/retest-candidates`, `PUT …/improvement-plan/{action_id}/retest` (`{retest_ttx_id, retest_objective_id}`): the Program Manager links an action of any of the organization's reports.

## `ttx_run.py` (the Playground's live session; `docs/features/playground.md`)
- `GET /ttx/{ttx_id}/run[?as={role}&since={cursor}]` (any participant: `RequiresOrgAndTTXAccess(*TTXContextRole)`; `as` marks the caller present as a role they hold; 204 while the cursor — log position + who is present — hasn't moved) → `RunRead`, projected per role: delivered injects only (`RunInjectRead`, no design fields), presence (team names hidden from Players), `facilitation` for a Facilitator, `control` (the whole MSEL to run) only for a Controller.
- Exports: `GET …/run/export/{log.pdf|log.csv|aar.pdf}?lang=` (Controllers, Planners, Lead Evaluator; 404 `EXPORT_NOT_FOUND`): the execution log and the draft after-action report. `?run=` names a previous run (logs only; 404 `RUN_NOT_FOUND` for another exercise's).
- Previous runs: `GET …/run/history` (same readers): the archived runs, latest first (`number`, `state`, `started_at`, `ended_at`, `stop_reason`, `has_report`).
- Feedback: `GET …/run/feedback` (form + whether the caller answered), `POST …/run/feedback?as={role}` (once the session is over, once per person, anonymous: 409 `RUN_NOT_OVER`, `FEEDBACK_ALREADY_SENT`), `GET …/run/feedback/results[?run=]` (Controllers, Planners, Lead Evaluator; aggregates, hidden under 3 answers; `run` names a previous run, 404 `RUN_NOT_FOUND`).
- Evaluation: `GET …/run/evaluation?room=` and `PUT …/run/ratings/{point_id}` (`{level, rationale, room_code?}`, `level: null` withdraws; in rooms each place on its own) — Evaluators of the exercise, once started (409 `RUN_NOT_STARTED`); only the EEGs the plan assigns them, all for the Lead Evaluator (403 `POINT_NOT_ASSIGNED`).
- Summary: `GET …/run/summary` (Controllers, Planners, Lead Evaluator; `docs/features/playground.md`).
- Stream: `GET …/run/stream?as={role}` (any participant): Server-Sent Events, `event: change` on every change of the session or presence, `: ping` keep-alives; background (never activity), ends when the session lapses.
- Decisions and votes (CSRF, each answering the caller's `RunRead` as `as`; while live or paused, hot wash included — after ENDEX the inject in play is `ENDEX` —, 409 `RUN_FINISHED` once over): `POST …/run/decisions?as=player|facilitator|controller` (`{text, inject_code?, room_code?}`: the inject in play by default, 409 `INJECT_NOT_RELEASED`; 404 `ROOM_NOT_FOUND`; any other role 403 `NOT_ACTING_AS`), `PUT|DELETE …/run/decisions/{id}?as=` (`{text}`; the author, a Facilitator or a Controller, else 403 `DECISION_NOT_YOURS`; 404 `DECISION_NOT_FOUND`); `POST …/run/polls?as=facilitator|controller` (Controllers and Facilitators; live only; `{question, options[2..6], room_code?}`; 422 `POLL_OPTIONS_REPEATED`; several may be open at once), `POST …/run/polls/{id}/close?as=` (`{record_option|null, outcome_option|null}`: that option recorded as a decision; the option whose consequence the table gets), `POST …/run/meters` (`{shown}`, Controller: the impact meters' summary to the Players), `GET …/run/meters?run=` (the team-note readers), `PUT …/run/polls/{id}/vote?as=player` (`{option}`; 409 `POLL_CLOSED`, 422 `POLL_UNKNOWN_OPTION`, 403 `POLL_NOT_YOUR_ROOM`; 404 `POLL_NOT_FOUND`). `POST /ttx/{id}/run/polls/{poll_id}/results` (`{shown}`, Controller, a closed planned poll only; 409 `POLL_STILL_OPEN`, `POLL_NOT_PLANNED`) shows a poll's result to the Players or hides it again; also once the session has ended.
- Notes: `GET`/`PUT …/run/notes?as={role}&room=` (the caller's own notes as that role; `PUT {inject_code, text, room_code?}` upserts, empty deletes; 403 `NOT_ACTING_AS`, 409 `INJECT_NOT_RELEASED`); `GET …/run/notes/team[?run=]` (Controllers, Planners, Lead Evaluator: every note but the Players'; `run` names a previous run).
- Any participant (CSRF, no step-up): `POST …/run/real-world` (`{keyword}`: the stop keyword, any case, else 422 `KEYWORD_MISMATCH`; live or paused, else 409) pauses the session for a real-world event (`RunRead.real_world_at` / `real_world_by`); idempotent; a Controller's `resume` clears it.
- Controller only (`TTXContextRole.CONTROLLER`, CSRF), each answering the new `RunRead`: `POST …/run/start` (409 `RUN_NOT_READY` unless the MSEL and the session plan are both READY; `RUN_ALREADY_STARTED`); `POST …/run/pause|resume|end`; `POST …/run/stop` (`{reason}`); `POST …/run/restart` (`{mode: delete|archive, confirmation}`: the typed word «restart», any case, else 400 `CONFIRMATION_MISMATCH`; no step-up; once ended or stopped, else 409 `RUN_NOT_FINISHED`; `delete` refused with `RUN_HAS_REPORT` when an after-action report rests on the run; `archive` keeps it as a previous run); `POST …/run/injects/{code}/release` (`{reason}` optional, required for a contingent: 422 `REASON_REQUIRED`; `INJECT_ALREADY_RELEASED`, `INJECT_SKIPPED`), `…/resend` (an inject already delivered goes back in play and the time since the last inject restarts; live only; 409 `INJECT_NOT_RELEASED`) and `…/skip` (`{reason}`); `POST …/run/endex` (`{title, content}`, the closing message to the table once every mandatory inject is released or skipped — 409 `INJECTS_PENDING` before; once only: afterwards release, resend, skip and a second ENDEX answer 409 `ENDEX_RELEASED`; it closes every phase, the run stays live); `POST …/run/questions` (`{phase_code, positions}`, onto the inject in play: `NO_INJECT_IN_PLAY`); `POST …/run/questions/covered` (`{phase_code, position, covered}`; Controllers **and Facilitators**; 409 `QUESTION_NOT_ASKED`); `PUT …/run/actions/{code}` (`{mark, note}`: `INJECT_NOT_RELEASED`); `POST …/run/inject-timer/reset` (restarts the time since the last inject on every screen, `RunRead.inject_timer_at` / `inject_timer_paused_seconds`; live or paused; 409 `NO_INJECT_RELEASED` before any release; each release restarts it too); rooms (`docs/features/rooms.md`; 409 `ROOMS_NOT_USED` at one table): `POST …/run/players/move` (`{to, user_ids?|room_code?}`; `PLAYER_WITHOUT_ROOM`), `POST …/run/main/project` (`{code|null}`; `INJECT_NOT_RELEASED`), `PUT …/run/seats` (`{assignments:[{user_id, room_code|null}]}`). While paused nothing is released (`RUN_PAUSED`); once ended or stopped, 409 `RUN_FINISHED`.
- `GET …/run/images/{image_id}`: an image of a delivered inject (every image of the played MSEL for a Controller; in rooms, a Player only those of injects their room or the main room was shown), else 404.
- `GET …/run/files/{file_id}`: a file of a delivered inject, same rule as images, always `application/octet-stream` as an `attachment`. `GET …/run/files/{file_id}/preview`: its beginning as plain text in JSON, same rule (409 `MSEL_FILE_NOT_TEXT` for a binary).
